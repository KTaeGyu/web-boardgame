# The Gang — 웹으로 옮긴 협력 포커

보드게임 **더 갱**(Thames & Kosmos, 2024)의 웹 구현. 브라우저만 있으면 된다.
설치할 것도, 계정을 만들 것도 없다. 방을 만들고 링크를 보내면 그게 전부다.

```
     브라우저 ──────── 화면 (Vercel) ──────── 소켓 서버 (Render)
                       정적 파일               방과 판이 사는 곳
```

---

## 어떤 게임인가

**서로 이기는 게임이 아니다.** 다 같이 금고를 털거나, 다 같이 잡힌다.

텍사스 홀덤과 진행은 같다. 홀카드 2장을 받고, 커뮤니티 카드가 3장 → 4장 → 5장으로
열린다. 다른 것은 **베팅이 없다**는 점이다. 대신 라운드마다 번호가 적힌 **토큰**을 집어
이렇게 말한다.

> 지금 내 손이 이 자리에서 몇 번째로 센 것 같다.

**카드 이야기는 금지다.** 무늬도, 숫자도, 「좋다」·「나쁘다」도 말할 수 없다.
토큰이 유일한 언어다. 남이 쥔 토큰을 뺏어올 수 있고, 뺏기면 다른 번호를 다시 집으면 된다.

마지막 라운드가 끝나면 **토큰 번호 순서대로 카드를 공개**한다.

| 결과 | 언제 | 표시 |
|------|------|------|
| 성공 | 약한 손 → 강한 손 순서가 맞았다 | 금고 하나가 열린다 |
| 실패 | 한 사람이라도 순서가 어긋났다 | 경보가 울린다 |

**금고 3개를 열면 승리, 경보가 3번 울리면 패배.** 그래서 한 게임은 아무리 길어야 다섯 판이다.

### 한 판의 흐름

```
  홀카드 2장   →   플롭 3장   →   턴 1장   →   리버 1장   →   공개
     │              │            │           │
   1라운드        2라운드      3라운드     4라운드
   토큰 집기      토큰 집기    토큰 집기   토큰 집기
```

라운드마다 **전원이 토큰을 하나씩 쥐어야** 다음으로 넘어간다. 카드가 한 장 더 열릴 때마다
내 손의 값어치가 달라지므로, 쥐고 있던 토큰을 놓고 다른 번호로 갈아탈 수 있다.

### 진행 방식 다섯

첫 판은 아무 카드 없이 시작한다. 그다음부터 **직전 판의 결과**가 다음 판을 정한다 —
성공했으면 판이 어려워지고(**도전자** 카드), 실패했으면 쉬워진다(**해결사** 카드).

| 모드 | 무엇이 다른가 |
|------|--------------|
| **기본** | 도전자·해결사 없이 순수한 규칙으로 |
| **고급** | 위의 성공/실패 규칙 그대로 |
| **프로** | 도전자 한 장이 게임 내내 붙어 있고, 그 위에 고급 모드가 얹힌다 |
| **마스터 시프** | 도전자 두 장이 언제나 걸린다. 해결사가 없고 경보 **두 번**이면 끝 |
| **직접 고르기** | 원작에 없다. 방장이 도전자를 고르고, 해결사는 **몇 번째 판에 나올지**까지 짠다 |

카드는 도전자 10장 · 해결사 10장, **스무 장 모두** 동작한다.
효과 전문은 [`docs/도전자-해결사-카드.md`](docs/도전자-해결사-카드.md) 에 있다.

### 인원

원작은 3~6인. 이 구현은 **3~10인**까지 받는다. 토큰 번호는 인원수만큼 생긴다.

## 빠르게 띄우기

**필요한 것** — Node **22.18 이상**. 그 밖에는 없다. 데이터베이스도 설치하지 않는다.

### 할 일

**1. 받고 설치한다**

```bash
git clone <저장소 주소>
cd the-gang
npm install
```

**2. 서버와 화면을 각각 띄운다** — 터미널 두 개가 필요하다

```bash
npm run dev:server    # 소켓 서버   :3001
```

```bash
npm run dev:web       # 화면        http://localhost:5173
```

**3. 브라우저로 연다**

<http://localhost:5173>

> **주의 — 여러 명을 흉내 내려면 새 탭이 아니라 새 창을 연다.**
> 정체성이 `sessionStorage` 에 있어서 창마다 다른 사람이 되지만,
> 같은 창의 새 탭은 앞 탭의 정체성을 물려받아 같은 사람으로 들어간다.
> 시크릿 창이 가장 확실하다.

> **주의 — 서버를 다시 띄우면 열려 있던 방이 전부 사라진다.**
> 상태가 전부 메모리에 있기 때문이다. 그 상태로 게임 화면을 새로고침하면
> 「방이 사라졌습니다」가 뜨고 목록으로 돌아간다.

### 확인해 볼 것

```bash
npm test          # 규칙 · 방 · 소켓 배선
npm run typecheck
curl localhost:3001/healthz     # {"ok":true,"rooms":0}
```

## 무엇이 어디에 있나

| 폴더 | 역할 | 배포 | 안내 |
|------|------|------|------|
| [`shared/`](shared/) | 카드·핸드 평가·쇼다운 판정·프로토콜. 서버와 화면이 **함께** 쓴다 | — | — |
| [`server/`](server/) | Socket.IO 게임 서버. 상태는 전부 메모리 | Render | [README](server/README.md) |
| [`web/`](web/) | React 화면 (Vite) | Vercel | [README](web/README.md) |

**데이터베이스를 쓰지 않는다.** 방보다 오래 사는 데이터가 하나도 없어서 뺄 수 있었다.
계정이나 전적처럼 서버 재시작을 넘겨야 하는 것을 넣으려면 그때 저장소가 따라온다.

**빌드 단계가 없다.** Node 22.18+ 의 네이티브 TypeScript 실행에 기대어 `shared` 와 `server` 는
`.ts` 를 그대로 돌린다. 그래서 `enum` 을 쓸 수 없고(strip-only), const 객체 + union 타입으로 쓴다.
`tsconfig` 의 `erasableSyntaxOnly` 가 실수를 잡는다.

## 정해진 것

되짚을 때마다 다시 논의하지 않으려고 적어 둔다. 결론과 **그 이유**가 함께 있다.

**방 식별자는 짧은 코드 문자열이다.** 방마다 포트를 여는 방식은 성립하지 않는다 —
Render 는 인스턴스당 포트를 하나만 열어준다. Socket.IO 의 room 으로 한 포트 위에서 나눈다.

**플레이어 식별자는 닉네임이 아니다.** 브라우저 `sessionStorage` 의 무작위 id 가 정체성이고
닉네임은 표시용이다. 동명이인이 서로를 덮어쓰지 않고, 새로고침해도 자기 자리로 돌아온다.

**은닉 정보는 공개 상태에 담기지 않는다.** `GameView` 에는 쇼다운 전까지 누구의 홀카드도
없다 — 본인 것조차 없다. 내 카드는 `game:hand` 로 나에게만 따로 간다. 미리 보내고 화면에서만
가리면, 통신을 열어보는 것만으로 답을 알 수 있다.

**화면은 서버가 확정한 뒤에 움직인다.** 낙관적 UI 는 뺏기가 잦은 이 게임에서 되돌리는 일이
많아 화면이 튄다.

**토큰 잠금은 토큰 단위이고, 화면 애니메이션과 같은 길이(0.5초)다.** 전역으로 잠그면 여러
명이 활발히 뺏을 때 서로의 입력을 계속 먹는다. 내가 쥐고 있다 중앙으로 돌아가는 토큰도
날아가는 동안 함께 잠근다 — 비행 중인 토큰을 낚아채면 화면이 무엇을 보여줘야 할지 알 수 없다.
잠금은 시간이 지나면 저절로 풀리지만 아무도 그 사실을 모르므로, 서버가 풀리는 시점에 상태를
한 번 더 보낸다. 같은 토큰을 노린 동시 요청은 Node 가 단일 스레드라 도착 순서가 곧 정답이다.

**토큰은 실제로 날아간다(FLIP).** 토큰이 중앙과 자리 사이를 옮기면 React 는 요소를 지웠다
새로 만들기 때문에 「같은 요소를 움직인다」로는 애니메이션이 붙지 않는다. 그리기 직전에 옛
위치를 기억했다가, 새 위치의 요소를 옛 위치에서 출발시킨다.

**게임 중 이탈은 10분 유예.** 끊긴 사람의 자리는 남기고 흐리게 표시한다. 돌아오면 그대로
복구하고, 넘기면 자리를 비운다. 방장이 사라지면 남은 사람 중 가장 먼저 들어온 사람에게
넘어가되 접속 중인 사람을 우선한다. 스스로 「나가기」를 누른 것은 끊김과 달라서 유예 없이
즉시 자리가 빈다.

**판이 도는 중에 누가 나가면 판을 접는다.** 라운드 종료 조건이 「전원이 확정」이라 한 명이
빠지면 영원히 끝나지 않는다. 끊긴 것은 나간 것이 아니므로 10분을 기다리고, 유예를 넘겨야
판을 접고 대기실로 되돌린다.

**끊김 유예(10분)와 방치 정리(30분)는 다른 이야기다.** 앞은 「연결이 살아 있는가」로,
새로고침이나 잠깐의 전파 끊김을 흡수한다. 뒤는 「사람이 실제로 하고 있는가」로, 접속만
걸어두고 떠난 방을 치운다. 무엇이든 하면 뒤쪽 시계가 다시 돈다.

**방 주소가 곧 방이다.** `/rooms/{코드}` 를 새로고침하거나 남에게 링크로 보내도 그대로
들어가진다. 정적 호스팅에서는 이 경로가 404 가 나므로 뿌리의 `vercel.json` 이 모든 경로를
`index.html` 로 돌린다.

**한 서버가 감당할 양에 한도를 둔다.** 동시 접속 100명, 동시 방 20개
(`MAX_CONNECTIONS`, `MAX_ROOMS`). 한도에 걸린 사람에게는 이유를 먼저 보내고 끊는다 —
아무 설명 없이 튕겨나가면 고장으로 느껴진다.

**자리와 관전은 다른 것이다.** 관전자는 방에 있지만 자리에 앉아 있지 않다 — 시작 인원에
들지 않고, 끊겨도 지켜줄 자리가 없어 그 자리에서 빠진다. 앉아 있던 사람이 스스로 물러날 수
있지만 대기실에서만이고, 혼자 있는 방에서는 물러날 수 없다. 방장이 물러나면 앉아 있는
사람에게 넘어간다 — 구경꾼은 방장이 될 수 없다.

**관전자에게 가려야 할 것은 손패뿐이다.** 공개 상태(`GameView`)에는 쇼다운 전까지 누구의
홀카드도 없으므로, 그대로 흘려도 새는 것이 없다. 은닉 정보의 통로를 하나로 묶어둔 덕에
관전을 붙이며 가리는 장치를 새로 만들 필요가 없었다.

**내보내기는 대기실에서만.** 판이 도는 중에 자리가 비면 라운드가 끝나지 않아 판이 통째로
접힌다. 그건 내보내기가 아니라 판을 엎는 것이라 다른 단추여야 한다. 차단은 고르는 것이고,
그 방에만 남는다 — 방이 사라지면 함께 사라진다.

**규칙이 붙지 않은 카드는 더미에 넣지 않는다.** 뽑히기만 하고 아무 일도 하지 않으면 규칙이
조용히 사라지는 셈이다. `extraCards.ts` 의 `ready` 가 그 표시이고, 지금은 20장 모두 켜져 있다.

**쇼다운은 「같거나 강하면」 통과.** 완전히 같은 손(true tie)은 순서와 무관하게 정답이다.
등호를 허용하는 것만으로 룰북의 true tie 가 자연히 풀린다.

## 핸드 평가 메모

- 로열 스트레이트 플러시는 별도 족보가 아니라 A탑 스트레이트 플러시다.
- A 는 양끝에 붙는다. `AKQJT` 가 최강, 휠 `5432A` 가 최약이며 이때 탑은 5 다.
- 무늬에는 우열이 없다. 키커까지 같으면 진짜 동점이고, 그것이 룰북의 true tie 다.
- 평가 결과는 족보 이름이 아니라 **사전식으로 비교 가능한 숫자 배열**(`score`)이다.
  우열뿐 아니라 「완전히 같음」까지 구분해야 하기 때문이다.
