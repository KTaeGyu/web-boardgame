# 화면

React + Vite. 만들어지고 나면 **정적 파일 한 묶음**이라 아무 데나 올려도 된다.
서버와는 소켓 하나로만 이야기한다.

> 전체 그림과 게임 규칙은 [뿌리 README](../README.md) 를 먼저 본다.

---

## 띄우기

### 할 일

**1. 저장소 뿌리에서 설치한다** — 이 폴더가 아니라 뿌리다

```bash
cd ..           # 저장소 뿌리
npm install
```

**2. 소켓 서버를 먼저 띄운다** — 화면만으로는 아무것도 못 한다

```bash
npm run dev:server      # :3001
```

**3. 화면을 띄운다**

```bash
npm run dev:web         # http://localhost:5173
```

> **주의 — 뿌리에서 설치해야 한다.**
> 이 폴더는 `@the-gang/shared` 의 **소스 `.ts`** 를 직접 가져다 쓴다.
> 빌드된 결과물이 아니라 소스라, 작업공간이 이어져 있지 않으면 못 찾는다.
> 같은 이유로 Vercel 의 Root Directory 도 `web/` 이 아니라 저장소 뿌리여야 한다.

> **주의 — 여러 명을 흉내 내려면 새 탭이 아니라 새 창을 연다.**
> 정체성이 `sessionStorage` 에 있어서 창마다 다른 사람이 되지만,
> 같은 창의 새 탭은 앞 탭의 정체성을 물려받는다. 시크릿 창이 가장 확실하다.

## 환경변수

| 이름 | 기본값 | 무엇 |
|------|--------|------|
| `VITE_SOCKET_URL` | `http://localhost:3001` | 소켓 서버 주소 |

> **주의 — 이 값은 빌드할 때 파일 안에 박힌다.** 실행 중에 읽지 않는다.
> 배포한 뒤에 값을 바꾸면 이미 만들어진 화면은 계속 옛 주소를 본다. 반드시 다시 빌드해야 한다.
> 화면은 멀쩡한데 영영 연결이 안 되는 모양으로 나타나서 알아채기 어렵다.

로컬에서 바꾸려면 이 폴더에 `.env.local` 을 만든다.

```
VITE_SOCKET_URL=http://localhost:3001
```

## 화면

| 주소 | 무엇 |
|------|------|
| `/` | 이름을 넣고 들어간다 |
| `/rooms` | 방 목록. 만들거나 골라 들어간다 |
| `/rooms/:code` | 대기실. 방장이 진행 방식과 카드를 정한다 |
| `/rooms/:code/game` | 판이 도는 곳 |

**방 주소가 곧 방이다.** 새로고침하거나 남에게 링크로 보내도 그대로 들어가진다.
정적 호스팅에서는 이 경로가 404 이므로 뿌리의 `vercel.json` 이 모든 경로를 `index.html` 로 돌린다.

## 파일 지도

| 파일 | 무엇 |
|------|------|
| `lib/socket.ts` | 연결은 **앱 전체에서 하나**다. 방을 옮겨도 끊었다 붙이지 않는다 — 끊김은 서버에서 「자리를 비울지」 판단의 근거라 함부로 만들면 안 된다 |
| `lib/identity.ts` | 내가 누구인가. `sessionStorage` 의 무작위 id |
| `lib/theme.ts` | 밝은 쪽·어두운 쪽 |
| `lib/tooltip.ts` | 커서를 따라다니는 카드 설명. 손가락은 길게 누르면 뜬다 |
| `lib/useTokenFlight.ts` | 토큰이 실제로 날아가게 하는 것(FLIP) |
| `lib/useViewportHeight.ts` | 모바일에서 키보드가 올라오면 화면 높이가 줄어든다 |
| `components/ExtrasDrawer.tsx` | 이번 판에 걸린 카드. 화면 옆에 카드 모양으로 붙어 있고 눌러서 뒤집는다 |
| `components/SpecialistGrid.tsx` | 「직접 고르기」에서 해결사를 **몇 번째 판에 둘지** 짜는 표 |
| `components/CardPicker.tsx` | 이름만 칩으로 흘려 두고 설명은 짚을 때만 |
| `components/Token.tsx` / `PlayingCard.tsx` | 토큰과 카드 |
| `components/ScanVote.tsx` / `SetupStep.tsx` | 다 같이 한 번씩 움직이는 단계 |
| `styles.css` | 색 토큰과 로비 |
| `game.css` | 게임 화면 |

## 색과 테마

**색은 전부 `styles.css` 맨 위의 토큰에서 나온다.** 밝은 쪽·어두운 쪽 두 벌이고,
어느 쪽인지는 늘 `<html data-theme>` 에 적혀 있다.

- 고른 적이 없으면 **기기 설정을 따른다**. 한 번 누르면 그 뜻이 이기고 `localStorage` 에 남는다.
- 어느 쪽인지는 **화면이 그려지기 전에** `index.html` 의 인라인 스크립트가 정한다.
  React 가 뜬 뒤에 붙이면 첫 한 칠이 어두운 채로 나왔다가 밝아져 눈에 띄게 깜빡인다.

> **색은 두 벌이지만 물건은 한 벌이다.**
> 트럼프 카드·토큰·초록 펠트는 두 테마가 같은 값을 쓴다 — 조명이 바뀐다고 트럼프가
> 검게 변하지는 않는다. 그래서 테이블의 초록(`--felt`)과 로비의 바탕(`--surface`)이 따로 있다.
> 처음에 둘을 한 토큰으로 뒀다가 밝은 쪽에서 초록 위에 검은 글씨가 났다.

새 색이 필요하면 하드코딩하지 말고 토큰을 하나 더 만든다.
불투명도가 필요하면 `rgba(var(--gold-rgb), 0.16)` 꼴로 쓴다.

## 다시 밟지 말 것

**미디어 쿼리는 파일 끝에 모은다.** 기본 규칙보다 앞에 두면 우선순위가 같아 나중에 오는
기본 규칙이 이긴다. 오류 없이 조용히 안 먹어서 두 번 헤맸다(모바일 캐러셀, 로고 크기).

**등장 애니메이션의 `fill` 은 `backwards` 다.** `both` 로 두면 끝난 뒤에도 `transform` 을
붙들어, 강조 같은 다른 변형이 먹지 않는다.

**폭을 정하지 않은 부모 안에서 `width: 100%` 는 아주 좁게 잡힌다.** 드로어가 그랬다.

**서버 상태 객체를 `useEffect` 의존성에 넣지 않는다.** 상태는 누가 토큰만 집어도 새로 오므로
매번 정리 함수가 돌아 타이머가 취소된다. 키 문자열 하나에만 맨다.

**손패가 바뀌는 경로를 빠뜨리기 쉽다.** 감지기가 카드를 갈아엎어도 새 손패를 보내지 않으면
화면에 옛 카드가 남는다. 지금은 라운드가 넘어갈 때 손패를 함께 보낸다.
