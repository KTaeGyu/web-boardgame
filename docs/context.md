# 더 갱 웹 — 지금 상태와 다음 할 일

보드게임 **더 갱**(협력 포커)의 웹 구현. 회사 업무가 아니라 개인 프로젝트다.
이 문서는 지금의 스냅샷이다. 설계 근거는 `README.md` 「정해진 것」, 카드 규칙 전문은
`docs/도전자-해결사-카드.md` 가 정본이고, 여기서는 **어디까지 왔고 무엇이 남았는지**만 다룬다.

## 무엇을 만들고 있나

3~10인이 브라우저에서 함께 하는 협력 포커. 텍사스 홀덤과 같은 진행이지만 베팅 대신
**토큰**을 집어 「내 손이 상대적으로 몇 번째로 센가」를 선언한다. 카드 이야기는 금지 —
토큰이 유일한 언어다. 마지막 라운드 토큰 순서대로 공개해 약→강이면 금고를 열고,
틀리면 경보가 울린다. 금고 3개면 승리, 경보 3개면 패배.

**게임은 규칙까지 완성됐고 돌아가고 있다.** 2026-08-25 에 처음 띄웠고, 2026-09-04 기준으로
아홉 번 배포됐다. **포커 방식이 다섯이다** — 텍사스 홀덤에 오마하·스팟스·서클잭·
바나나스플릿이 붙었다(2026-09-02~03). 친구들에게 뿌려 놓은 상태이고, 지금 하는 일은 두 가지다 — **돌려보며
드러나는 것을 줍는 일**과, 그러다 「이건 아예 다르게 있어야겠다」 싶은 것을 옮기는 일
(계정·진입점·혼자 해보기·코스메틱 상점이 그렇게 나왔다).

**규칙이 하나 바뀌었다**(2026-09-03). 해결사는 「먼저 누른 사람이 쓴다」가 아니라
**누가 쓸지를 만장일치 투표로 정한다.** 누가 쓰느냐로 판이 갈리는 카드들이라(「정보원」을
누가 누구에게, 「근육」을 누가) 그 판단이 한 사람 손에 떨어져 있었다. 카드 이야기가 금지된
게임에서 표는 말이 되고, 스캔이 이미 그 어법을 쓴다.

본다. 절차와 함정은 `docs/배포.md` 가 정본이다.

## 지금 돌려보려면

```bash
cd 개인프로젝트/the-gang
npm install
npm test              # 472개
npm run typecheck
npm run dev:server    # 소켓 서버 :3001
npm run dev:web       # 화면 http://localhost:5173
```

사람들과 하는 판은 둘 다 띄워야 한다. **혼자 해보기는 `dev:web` 만으로 돈다** — 판이 화면
안에서 돌기 때문이고, 그게 그 기능을 옮긴 이유다. 여러 명을 흉내내려면 **새 탭이 아니라
새 창**(또는 시크릿 창)으로 연다 — 정체성이 `sessionStorage` 에 있어서 탭마다 다른 사람이
되지만, 같은 창의 새 탭은 세션을 물려받을 수 있다.

**계정을 로컬에서도 쓰려면** 저장소 뿌리에 `.env` 를 만들고 Contentful 값 셋을 넣는다
(`docs/배포.md` 참고). 없으면 계정이 메모리에만 남을 뿐 나머지는 그대로 돈다.

**서버를 다시 띄우면 방과 판이 전부 사라진다.** 그것들은 메모리에만 있다. 그 상태에서 게임
화면을 새로고침하면 「방이 사라졌습니다」가 뜨고 목록으로 돌아간다. **계정만 예외로 살아남는다**
— Contentful 에 한 벌 있기 때문이다.

## 무엇이 잘못됐는지 어디서 보나

로컬에서는 오류가 `logs/` 에 파일로 쌓인다(2026-08-31). 화면 층에는 테스트 러너가
없어 무엇이 났는지 사람이 보고 옮겨 적어야 했는데, 그 자리를 파일 둘로 바꿨다.

| 파일 | 누가 쓰나 | 언제 처음부터 다시 쓰나 |
|------|-----------|------------------------|
| `logs/server.log` | 소켓 서버 (`server/src/log.ts`) | 서버를 다시 띄울 때 |
| `logs/web.log` | 화면 개발 서버 (`web/vite.config.ts` 의 플러그인) | 개발 서버를 다시 띄울 때 |

**쌓지 않고 덮어쓴다.** 파일이 하나씩 늘면 어느 것이 이번 판의 것인지 고르는 일이
먼저가 된다. 서버를 다시 띄우면 어차피 방이 전부 사라지므로, 그 이전의 줄은 지금
벌어지는 일과 이어지지도 않는다.

브라우저는 파일을 쓸 수 없으므로 화면은 `/__log` 로 보내고 개발 서버가 받아 적는다.
받는 자리를 소켓 서버가 아니라 Vite 에 둔 것은 두 가지 때문이다 — 화면과 같은 출처라
CORS 를 열 일이 없고, **파일의 수명이 화면 개발 서버와 같아진다.**

무엇이 남는가.

- 아무도 받지 않은 오류 · `console.error` · `console.warn` (양쪽 모두)
- **거절당한 요청** — `deny` 로 표시된다. 거절은 예외가 아니라 값이라 어디에도
  남지 않던 것이다. 화면이 사람에게 말을 보이고 끝내므로, `call()` 을 지날 때만 볼 수 있다.
- **연결이 오간 시각** — `sock`. 화면의 여러 자리가 「붙어 있는가」로 잠기는데,
  끊긴 것을 화면만 모르고 있으면 「눌러도 아무 일이 없다」로 보인다. 그 둘을 가르는 값이다.

한 화면이 남기는 줄은 500개까지다. 되풀이되는 오류는 끝이 없어서, 한도가 없으면
파일이 같은 줄로만 채워져 정작 처음에 무엇이 났는지가 앞쪽에 묻힌다.

**운영에는 없다.** 서버는 `NODE_ENV=production`(render.yaml)이면 아무것도 쓰지 않고,
화면 쪽은 `import.meta.env.DEV` 가 false 라 알맹이가 배포본에서 통째로 떨어져 나간다
(빌드 산출물에 `__log` 가 하나도 없는 것으로 확인했다). 받는 자리도 개발 서버에만 있다.

**테스트는 이 길을 밟지 않는다.** 파일 로그는 `index.ts` 에서만 켜지는데 테스트는
`app.ts` 를 직접 쓴다. 그래서 몇 개를 돌리든 `logs/` 는 그대로다.

## 구조

| 폴더 | 역할 | 배포 |
|------|------|------|
| `shared/` | 카드·핸드 평가·쇼다운 판정·프로토콜, 그리고 **판을 진행하는 엔진**. 서버와 웹이 함께 쓴다 | — |
| `server/` | Socket.IO 게임 서버. 방과 계정은 메모리 | Render |
| `web/` | React 클라이언트 (Vite) | Vercel |

**엔진이 `shared/` 에 있는 것이 요점이다**(2026-08-31에 `server/` 에서 옮겼다). 혼자 해보기가
화면 안에서 돌기 때문인데, **규칙이 두 벌로 갈리지 않는 것**이 그 이유의 전부다 — 서버와
화면이 같은 `Game` 을 쓴다. 배럴(`index.ts`)이 아니라 하위 경로(`@the-gang/shared/engine`)로
내보낸다. 배럴에 얹으면 `index → engine → index` 로 돌아온다.

**DB 는 없지만 저장소는 하나 있다.** 방과 판은 여전히 메모리뿐이라 서버를 다시 띄우면
사라진다 — 방보다 오래 살아야 할 것이 없어서다. **계정만 예외**로 Contentful 에 한 벌
남긴다(2026-08-31). 「가입」이라는 말이 15분 뒤에 거짓이 되면 안 되기 때문이고, 그것 하나를
위해 관계형 DB 를 들이지 않았다. 자세한 것은 아래 「계정을 서버 밖에 남긴다」.

계정 항목에는 이메일·닉네임·비밀번호 해시·전적 외에 **`cosmetics` 칸(Object, 비어도 됨)**이
있다(2026-09-04). 구매한 것·장착한 것·사용한 골드가 한 칸에 묶여 있다 — 슬롯이 늘 때마다
저장소 스키마를 손대지 않으려고 그렇게 두었다. 비어 있으면 기본 차림이다.

Node 22.18+ 의 네이티브 TS 실행에 기대어 `shared` 와 `server` 는 **빌드 단계가 없다**.
그래서 `enum` 을 쓸 수 없다(strip-only). const 객체 + union 타입으로 쓰고,
tsconfig 의 `erasableSyntaxOnly` 가 실수를 잡는다.

## 규칙이 어디에 있나

- `shared/src/variants.ts` — **어떤 포커인가.** 몇 장을 받고 · 언제 몇 장이 열리고 ·
  그중 무엇으로 손을 만들고 · 덱 52장이 몇 자리를 감당하는가. **판은 이 표를 따를 뿐
  어떤 포커인지 모른다.** 변형을 더할 때 손댈 곳이 여기 하나다.
- `shared/src/handEval.ts` — 7장 중 최선의 5장. 사전식으로 비교 가능한 `score` 배열을 준다.
  우열뿐 아니라 **완전히 같음**까지 구분해야 해서 족보 이름이 아니라 배열이다.
- `shared/src/showdown.ts` — 「앞사람보다 같거나 강하면 통과」. 등호를 허용하는 것만으로
  룰북의 true tie 가 자연히 풀린다. 「근육」이 걸리면 같은 족보끼리의 우열이 뒤집힌다.
- `server/src/rooms.ts` — 방. 소켓도 시계도 모른다. 시간을 주입받아 재접속 유예를
  타이머 없이 테스트한다.
- `shared/src/engine.ts` — 한 판의 진행과 **걸린 카드가 무엇을 하는가**. 서버와 화면이
  같은 것을 쓴다.
- `shared/src/extraDealer.ts` — **어느 판에 무엇이 걸리는가**(모드별 뽑기). 규칙과 갈라두어야
  각각 따로 검증된다.
- `shared/src/tutorial.ts` — 봇이 언제 무엇을 누르는가, 어디서 멈춰 무엇을 알려주는가.
- `server/src/socket.ts` — 배선만. 누가 무엇을 듣는지.
- `web/src/lib/localGame.ts` — 혼자 해보기의 배선. 위 socket.ts 의 게임 부분과 짝이다.
- `web/src/components/Board.tsx` — 공용 카드를 그 방식의 **모양**대로 늘어놓는다. 테이블 ·
  쇼다운 모달 · 스캔 창 **세 군데가 이것 하나**를 쓴다. 모양이 곧 규칙인 변형에서는
  한 곳만 어긋나도 「어느 줄로 만든 손인지 알 수 없음」이 된다.
- `web/src/components/PickList.tsx` — 하나만 고르는 설정. `CardPicker` 는 여럿 고르는
  목록(도전자 카드)만 맡는다.
- `shared/src/cosmetics.ts` — **무엇을 장착할 수 있고 몇 골드인가.** 슬롯 넷의 아이템
  목록과 가격, 골드 셈, 낡은 값 되돌리기. **가격이 짜거나 후하면 이 표의 숫자만 고친다**
  — 서버가 이 표로 판정하고 화면은 같은 표를 보여줄 뿐이라 고친 순간 양쪽이 함께 갈린다.
  **아이템 이름도 여기 한 벌**이고, 남의 상표는 이름 후보에서 먼저 걸러낸다.
  그림은 여기 없다(이름표로 `web/public/avatars|banners/` 를 찾는다).
- `shared/src/emotes.ts` — 감정표현 목록과 **되돌릴 값 셋**(간격 `EMOTE_COOLDOWN_MS`,
  떠 있는 시간, 내려가는 시간). 카드 이야기를 우회하는 신호가 문제가 되면 첫 값을 올린다.

## 붙어 있는 것

**카드 20장 전부**(도전자 10 · 해결사 10)와 **모드 5종**, 그 위에 **포커 방식 5종**이 돈다.
모드는 기본 · 고급 · 프로 · 마스터 시프 + **직접 고르기**(원작에 없는 모드, 방장이 카드를 고른다).
포커 방식은 텍사스 홀덤 · 오마하 · 스팟스 · 서클잭 · 바나나스플릿이고, **모드와는 층이 달라
둘이 곱해진다** — 오마하로 프로 모드를 할 수 있다.

화면은 메인(`/`) · 방 목록(`/rooms`) · 상점(`/looks`) · 대전기록(`/history`) ·
방(`/rooms/:code`) · 게임(`/rooms/:code/game`) · 관전(`/rooms/:code/watch`).

**코스메틱과 감정표현**(2026-09-03~04). 대기실 한 줄이 슬롯 넷으로 선다 — 바깥부터
**배너 > 이펙트 > 프로필 배경 > 아바타**. 가격은 **골드**로 내는데, 누적 승리에서
사용한 만큼을 뺀 값이다(`wins - spent`) — 전적 자체는 깎이지 않는다. **로그인한 사람만
장착한다**(계정에 남을 자리가 있어야 하므로). 감정표현은 반대로 **게스트도 한다** —
남지 않는 말이고, 이미 자유 채팅이 열려 있어 그것만 막으면 뜻이 없다.
대기실을 관전 중이면 주소에 `?watch=1` 이 붙는다.

**가격은 두 축으로 정한다**(2026-09-04). 슬롯끼리는 무게 순이고(아바타 30~42 > 배너
20~25 > 이펙트 12~16 > 프로필 배경 4~6), **한 슬롯 안에서는 1.5배 안쪽으로 좁게** 벌린다 —
같은 자리에 걸치는 것끼리 값이 두세 배로 갈리면 고르는 축이 「무엇이 나다운가」가 아니라
「무엇을 살 수 있나」가 된다. 그 안의 순서는 화려함이고, 조각 수보다 **실루엣이 바뀌는가**가
무겁다. 표는 `shared/src/cosmetics.ts` 한 벌뿐이고 시험도 거기서 값을 읽는다.

**아이템은 28가지다**(2026-09-04). 아바타 8 · 프로필 배경 7 · 이펙트 6 · 배너 7
(슬롯마다 0골드짜리 기본이 하나씩 끼어 있다). 강도단
얼굴만 늘어놓으면 고를 결이 하나뿐이라 **치즈와 토끼** 두 갈래를 얹었다 — 체다 · 화이트
래빗 · 머스터드 · 캐럿 · 멜팅 · 홉 · 치즈 팩토리 · 문라이트 힐. 그림은 있던 어법을
그대로 따른다(아바타는 64×64 둥근 상자, 배너는 240×48 에 무늬를 오른쪽으로 몰아 왼쪽을
글자 자리로 비운다). **「홉」만 결이 다르다** — 옆에 조각을 붙이지 않고 얼굴 자체를
튀게 하는 유일한 이펙트다.

**상점은 구매만 확인을 받는다**(2026-09-04). 장착은 언제든 되돌리지만 구매는 되돌릴
길이 없고, 42골드짜리가 30골드짜리 옆 칸에 서 있다. 확인창에는 입혀 본 모습과
**치른 뒤의 잔액**을 담는다 — 판단에 쓰이는 값은 지금 잔액이 아니라 쓰고 난 잔액이다.

**넓은 화면(721px~)의 상점은 두 칸이다.** 왼쪽에 차림·골드·안내가 붙박이고(sticky)
오른쪽에서 고른다. 슬롯 넷의 조합이 곧 꾸미기라 고른 것이 즉시 얹히는 것을 보면서
골라야 하고, 격자를 내리는 사이에 잔액이나 거절 사유가 눈에서 사라지면 안 된다.
좁은 화면은 420px 한 줄로 쌓이던 그대로다.

카드를 온라인으로 옮기며 생긴 장치가 여럿이다.

- **드로어** — 이번 판에 걸린 카드가 화면 옆에 카드 모양(5:7)으로 붙어 있다. 마우스를 올리면
  설명이 커서 옆에 뜨고, 누르면 뒤집혀 설명·결과·쪽지가 나온다. 해결사는 뒷면에서 쓴다.
- **해결사를 쓰는 단추는 앞뒤 양면에 있다**(2026-09-03). 뒤집어야만 나오면 「어떻게 쓰나」가
  한 번 더 물어야 하는 물음이 된다. 앞면 단추는 「눌러서 뒤집기」가 있던 자리를 쓰고,
  눌러도 카드가 뒤집히지 않는다. 뜨는 조건은 **서버가 보는 것과 같아야 한다**
  (`Game.useSpecialist`) — 해결사가 걸렸고 · 아직 안 썼고 · 토큰 고르는 중이고 ·
  **자리에 앉은 사람**일 때. 마지막 것이 빠져 있어 구경꾼에게도 단추가 떴다.
  - **거절을 삼키지 않는다.** 확인창은 누르는 순간 닫히므로, 실패하면 「눌렀는데 아무 일도
    안 일어났다」로만 남는다. 실제로 두 갈래가 있다 — 남이 한발 먼저 눌렀을 때, 그리고
    창을 열어둔 사이에 라운드가 넘어갔을 때(마지막 라운드면 그대로 쇼다운으로 간다).
  - **대상은 접속 중인 사람만** 고른다. 자리 비운 사람을 고르면 카드는 쓰였는데 알려줄
    소켓이 없어 쪽지가 어디에도 닿지 않는다 — 그 판의 해결사가 그냥 사라진다.
- **쪽지** — 카드가 나에게만 알려주는 것은 `game:note` 로 그 사람 소켓에만 간다.
  도착하면 한 번 뜨고, 뒤에는 드로어에서 다시 본다.
- **해결사 배치표** — 「직접 고르기」에서 해결사는 고르는 것이 아니라 **판을 지정한다.**
  가로 한 줄이 카드, 세로 한 칸이 판이다. 세로로는 하나만 서지만(한 판에 한 장)
  가로로는 여럿이어도 된다 — 같은 카드를 1판부터 5판까지 내리 세워도 된다. 「썼는가」가
  판마다 새로 시작하기 때문이다. 빈칸도 뜻이 있어서, 다섯째 칸에만 찍으면 앞의 네 판은
  해결사 없이 지나간다. 이렇게 판별로 짤 수 있다는 것이 다른 모드와 갈리는 지점이다.
- **몇 판짜리 게임인가도 방장이 정한다**(2026-08-25). 「직접 고르기」에서 금고와 경보를
  각각 1~5 로 둔다. 다른 모드는 원작 그대로 3 · 3 이고 마스터 시프만 경보가 2다.
  **배치표의 자리 수가 여기서 나온다** — 판수는 「승 + 패 - 1」이라(둘 다 하나씩 모자란 채로
  맞서면 그다음 판에서 결판난다) 금고를 늘리면 배치표도 함께 늘고, 줄이면 없어질 판에 서
  있던 해결사가 사라진다. 표를 다시 보내라고 하는 대신 서버가 길이를 맞춘다(`fitRounds`).
  금고 눈금도 상수가 아니라 서버가 보낸 수만큼 그린다(`GameView.vaultsToWin`).
- **무작위 도전자**(2026-08-26 개정). 「직접 고르기」에서 고른 것 위에 최대 세 장을 더 얹는다.
  **판마다 새로 뽑는다** — 고른 카드(고정)와는 겹치지 않고, 지난 판에 나왔던 카드는 다시
  나올 수 있다. 처음에는 시작할 때 한 번만 뽑았는데, 그러면 「무작위」라기보다 「몰라서 고른
  고정」이었다. 무작위만 얹고 아무것도 고르지 않아도 시작할 수 있다 — 걸릴 카드가 있는
  것이라 「고른 것이 없다」에 들지 않는다.
  - **이긴 다음에만**(기본 꺼짐) — 원작의 「성공하면 어려워진다」를 쓰고 싶을 때 켠다.
  - **누적**(기본 꺼짐) — 한 번 나온 카드가 그대로 남아 판이 갈수록 쌓인다. 이미 걸린
    카드는 다시 뽑지 않으므로 매 판 새 카드가 그만큼 더해진다.
  - 고른 카드는 두 조건과 무관하게 늘 걸린다. 그것이 「고정」의 뜻이다.
  - 빠른 접근 ↔ 감지기는 뽑는 자리에서 지킨다. 이미 걸려 있는 것과 부딪히는 카드는
    애초에 후보에서 뺀다.
- **해결사의 조건과 무작위**(2026-08-26). 배치표에 **맨 윗줄 「무작위」**가 생겼다. 찍어둔
  판에서는 그 자리에서 한 장을 뽑는다. 한 판에 해결사는 하나뿐이라 지정 카드와 같은 칸에
  함께 설 수 없고, 나중에 찍은 쪽이 자리를 가진다. **「진 다음에만」은 기본으로 켜져 있다** —
  원작에서 해결사는 실패한 판을 거들어주는 카드다. 끄면 결과와 무관하게 표대로 나온다.
  - **조건을 켜 두면 첫 판에는 나오지 않는다.** 「직전 판을 졌을 때」인데 직전 판이 없다.
    1판에 찍어두고 조건을 켜 두면 그 칸은 영영 안 나온다는 뜻이라, 화면에 그 사실을 적었다.
- **뒤로가기**(2026-08-26). 휴대폰의 뒤로가기는 브라우저 뒤로가기와 같은 것이라, 그냥 두면
  화면이 통째로 바뀐다. 세 층으로 갈라 받는다 — **덮개가 떠 있으면 덮개만 닫고**(확인창·
  선택창·대화·서랍·연습 안내), **판이 도는 중이면 「나갈까요?」를 묻고**, **대기실이면
  방에서 나간다**(자리를 비우고 관전 목록에서도 빠진다). 방법은 하나뿐이다 — 지킬 것이
  있는 동안 히스토리에 빈 칸을 하나 쌓아 두고(`web/src/lib/back.ts`), 뒤로가기가 그 칸을
  먹을 때 대신 처리한다. 주소는 그대로다.
  - 판에서 그냥 나가게 두면 화면만 목록으로 가고 자리는 남아, **라운드가 내 확정을
    기다리며 선다.** 남들 화면에는 아무 일도 없는데 판만 멈춘다.
  - **보이는 층 하나에 칸 하나다.** 확인창이 뜨는 동안에는 그 아래 층의 가드를 아예
    내려놓고(`active` 를 끈다), 창이 닫히면 다시 세운다. 한 층이 칸을 둘 쌓기 시작하면
    셈이 어긋나 확인창이 되풀이된다 — 실제로 그렇게 났다.
  - 신호를 받는 자리도 하나다. 지키는 것들을 쌓아 두고 **가장 나중에 쌓인 것 하나**에만
    넘긴다. 각자 리스너를 달면 한 번의 뒤로가기를 여럿이 나눠 먹는다.
  - 단추로 닫혔으면 자기 칸을 도로 걷어낸다. 남기면 뒤로가기 한 번이 헛돈다. 자기 칸이
    없으면(뒤로가기가 이미 먹었으면) 손대지 않는다 — 남의 칸을 걷어내게 된다. 라우터가
    화면을 옮기며 정리하는 경우에도 맨 위가 이미 라우터의 칸이라 건드리지 않는다.
- **작은 화면의 시트**(2026-08-26). 640px 아래에서는 뜨는 것들이 아래에서 올라오는 시트가
  된다. 폭은 화면 끝까지, 높이는 `--app-height` 기준이다(키보드가 올라온 만큼 줄어야 대화
  입력칸이 안 가린다). 연습 안내만 위에 남는다 — 아래에 붙이면 「토큰을 누르세요」가
  가리키는 그 토큰을 덮는다.
- **포커 족보표**(2026-08-31). 오른쪽 위 도구 줄의 스페이드 단추. 강한 것이 위로 열 줄이고,
  줄마다 예시 다섯 장을 놓되 **족보를 이루는 카드만 남기고 나머지는 어둡게 덮는다** —
  이름만 늘어놓으면 「투 페어가 뭐였더라」에 답이 안 되고, 다섯 장을 다 진하게 두면
  어디까지가 족보인지가 안 보인다. 이름은 `CATEGORY_LABEL` 을 그대로 쓴다. 화면이 부르는
  이름과 쇼다운이 부르는 이름이 갈리면 표를 보고도 제 결과를 못 찾는다. 로열 스트레이트
  플러시만 코드에 없는 줄이다 — 따로 세는 갈래가 아니라 스트레이트 플러시 중 제일 높은
  것인데, 가장 센 손이 무엇인지가 표에서 바로 보여야 해서 줄을 나눴다.
  판이 도는 중에 급해지는 물음이라 어느 화면에서나 열린다. 대화로 물으면 카드 이야기가
  되어 규칙에 걸린다.
- **하나만 고르는 자리는 눌러서 펼친다**(2026-09-03, `PickList`). 포커 방식과 진행 방식이
  칩 다섯씩 열 개로 늘어서 화면 한 판을 먹었다. **닫혀 있으면 한 줄, 펼치면 이름만** 선다.
  `<select>` 를 쓰지 않은 것은 **설명을 붙일 자리가 없어서**다 — 네이티브 목록은 브라우저가
  그려서 말풍선도 `title` 도 안 붙고 휴대폰에서는 방법이 없다. 처음 보는 포커 다섯 개를
  고르는 자리라 그것이 결정적이었다.
  - **설명은 다른 설정과 같은 손짓으로 읽는다**(`useCardTip`). 한 번은 목록 안에 설명을
    깔아 봤는데 다섯 줄이 열다섯 줄이 되어, 펼치는 뜻이 반쯤 사라졌다.
  - 펼친 목록은 **흐름 밖으로 띄운다** — 자리를 밀어내면 고를 때마다 아래 설정들이
    통째로 오르내린다.
  `CardPicker` 는 이제 **여럿 고르는 목록(도전자 카드)만** 맡는다.
- **설정의 설명은 짚을 때만 뜬다**(2026-09-03). 대기실의 설정 칸마다 밑에 두세 줄씩
  깔려 있던 글을 말풍선으로 옮겼다 — 휴대폰에서는 설정 하나를 보려고 화면을 몇 번씩
  밀어야 했다. 손짓의 규칙은 카드 고르기와 같은 한 벌이다(`useCardTip`): **마우스는
  올리면, 손가락은 누르면** 뜬다. 옮긴 자리에는 `?` 표식을 붙인다 — 없으면 짚어 볼 것이
  있다는 사실 자체를 모른다.
  - 좁은 화면에서는 **고른 것의 설명(`.pick-picked`)도 감춘다.** 포커 방식과 진행 방식은
    늘 하나가 골라져 있어 그 설명이 붙박이로 깔리는데, 다섯씩 둘이라 그것만으로 화면 한
    판이 찬다. 칩을 누르면 같은 글이 그 자리에서 뜨므로 잃는 것이 없다.
  - **참여자 줄도 짚을 수 있다.** 잘린 이름 전체와 「방장」·「자리 비움」의 뜻이 뜬다.
- **화이트/다크** — 오른쪽 위 단추 하나로 바꾼다. 한 번도 누르지 않았으면 기기 설정을 따르고,

  누른 뒤에는 그 뜻이 이긴다(`localStorage`). 어느 쪽인지는 늘 `<html data-theme>` 에 적혀 있다.
- **다 같이 하는 단계** — 정해진 시점에 전원이 한 번씩 움직인다. 「조율가」·「사기꾼」은 딜 직후,
  스캔(「망막」·「지문」)은 마지막 사람이 공개되기 전. 스캔은 표가 서로 보여서 말 없이도
  만장일치로 옮겨간다. 둘 다 걸리면 둘 다 맞혀야 한다.

- 채팅이 있다(2026-08-25). 원작의 「카드 이야기 금지」는 사람끼리 지키는 약속이지 화면이
  막을 일이 아니라고 보고 넣었다. 대화는 **방에 속한다** — 대기실에서 판으로, 판에서 다시
  대기실로 이어지고, 방이 닫히면 함께 사라진다. 서버가 마지막 50줄을 들고 있다가 들어올 때
  건네고, 창은 `sessionStorage` 에 300줄까지 따로 들고 있다가 번호로 합친다.
  번호는 **방마다** 센다 — 그래야 「번호가 안 이어짐 = 사이가 빠짐」이 성립해서
  「이 사이의 대화는 남아 있지 않습니다」를 정확한 자리에 그릴 수 있다.
- 번호만으로는 같은 방인지 알 수 없다. 방 번호는 네 자리라 닫힌 방의 번호가 다시 쓰이는데,
  그러면 창에 남은 옛 대화가 남의 새 방에 섞인다. `chat:history` 가 **방이 열린 시각**을
  함께 건네고, 창은 번호와 시각이 둘 다 같을 때만 이어 붙인다.
- **내보내기**(2026-08-25). 방장이 **대기실에서만** 쓴다 — 판이 도는 중에 자리가 비면
  라운드가 끝나지 않아 판이 통째로 접히는데, 그건 내보내기가 아니라 판을 엎는 것이다.
  차단은 고를 수 있게 두었다(그냥 내보내기 / 차단하기). 차단은 그 방에만 남고 방이 닫히면
  함께 사라진다.
- **관전**(2026-08-25). 자리 없이 보기만 한다. **공개 상태에 홀카드가 원래 없어서**
  가리는 장치를 새로 만들 필요가 없었다 — 손패(`game:hand`)만 안 가면 된다.
  - 대기실에서도 판에서도 볼 수 있고, 앉아 있던 사람이 스스로 물러날 수도 있다(대기실만).
    혼자 있는 방에서는 물러날 수 없고, 방장이 물러나면 앉은 사람에게 넘어간다 —
    구경꾼은 방장이 될 수 없다.
  - **자릿수는 방장이 정한다**(2026-08-31, 0~5). 0 은 「관전을 받지 않음」이다. 이미 보고
    있는 사람보다 적게 줄일 수는 없다 — 줄이는 것이 곧 내보내는 것이 되면 설정 한 칸이
    사람을 쫓아내는 단추가 된다.
  - **자리가 정원 밖이라, 정원이 찬 방에도 관전으로는 들어간다.** 목록이 그 방을 잠그지
    않고 창 안에서 「들어가기」만 잠근다 — 선택지를 지우면 왜 안 되는지도 함께 사라진다.
  - 시작 인원에 들지 않고, 지켜줄 자리가 없으므로 끊기면 그 자리에서 빠진다.
    말은 할 수 있되 「관전」 표시가 붙는다.

- **계정과 전적**(2026-08-31). **이메일로 사람을 가리키고 전적을 이어 준다.** 유일한 것은
  이메일뿐이고 **닉네임은 겹쳐도 된다** — 테이블에서 같은 이름이 둘이면 예전처럼 [1] [2] 가
  붙는다. 그래서 계정은 이름을 붙들어 두지 않고, 방에 들어가는 자리(만들기·들어가기·관전)는
  계정을 아예 보지 않는다. 처음에는 「이름 선점」이 계정의 존재 이유였는데, 이메일을 식별자로
  삼으면서 그 장치(`nameFree`·요청마다 싣던 표)를 통째로 걷어냈다.
  - 이메일은 **보내서 확인하지 않는다.** 주인임을 증명하는 값이 아니라 사람이 자기 것으로
    알아볼 만한 유일한 글자로 쓴다. 그래서 규격을 끝까지 따지지 않고 오타에 가까운 것만
    거른다 — 엄하게 잡으면 멀쩡한 주소가 막힌다.
  - 비밀번호는 scrypt 해시다. 밖에 저장되는 값이라 평문으로 두면 그 표를 찍어보는 코드
    한 줄에 새어 나간다. 없는 이메일과 틀린 비밀번호는 **같은 말**로 돌려보낸다 — 갈라
    말하면 어느 주소가 쓰이는지 물어보는 것만으로 알 수 있다. 친구들끼리 하는 판이라
    지킬 것이 적지만 사람들은 다른 데서 쓰던 것을 치므로, 그러지 말라고 칸 밑에 적었다.
  - **표는 `sessionStorage`** 다. 정체성(`playerId`)과 같은 자리라 새로고침은 넘기되
    새 창까지 따라가지 않는다. `localStorage` 로 옮기면 따라오지만 한 브라우저에서
    여러 명으로 붙어 볼 수 없게 된다. 대신 한 계정에 표를 여럿 뗄 수 있다 —
    자리를 묶는 것은 이메일이지 표가 아니다.
  - **전적은 이긴 판과 진 판뿐이다.** 도중에 나간 판은 아무 줄도 남기지 않는다 — 판이
    어떻게 끝났는지 모르는 채로 자리를 뜬 것이라 승도 패도 아니다. 기기(`localStorage`)
    기록은 2026-08-31 에 없앴다. 같은 것이 두 곳에 있으면 어느 쪽이 진짜인지 매번 골라야
    하고 두 수가 어긋난 채로 나란히 선다. 게스트로 한 판은 세지 않는다.
  - 판의 끝은 **화면이 판정해 보낸다**(`auth:record`). 서버가 스스로 세지 않는 것은
    끝을 아는 자리가 화면 쪽에 흩어져 있어서다. 조작할 수 있는 자리지만 친구들끼리 하는
    판이라 그대로 두었다. 서버가 직접 세려면 게임 흐름에 끝나는 지점을 하나로 모으는
    일이 먼저다.
  - **게스트로 하기**는 아무것도 부르지 않는다. 닉네임만 치고 방 목록으로 간다.

- **계정을 서버 밖에 남긴다 — Contentful**(2026-08-31). 서버 메모리는 다시 띄우면 비어
  있고 무료 요금제는 15분 무트래픽에 잠든다. 계정까지 그때 사라지면 「가입」이라는 말이
  거짓이 되므로, 계정을 밖에 한 벌 둔다. **`server/src/accountStore.ts` 한 파일이 그 자리**이고
  `Accounts` 는 그것을 주입받는다 — 환경변수가 하나라도 없으면 `null` 이 들어가 예전처럼
  메모리만으로 돈다. 테스트와 로컬이 자격증명 없이 그대로 돌아야 해서다.
  - **읽는 것은 부팅 때 한 번뿐이다.** 로그인도 전적 조회도 메모리만 본다. 그래서
    **관리 API(CMA)만 쓴다** — 읽기용 API 는 CDN 캐시라 방금 쓴 것이 몇 초 늦게 보이고,
    보이게 하려면 발행(publish)을 한 번 더 불러야 한다. 그 이점이 필요 없으므로 두 가지를
    통째로 건너뛴다. SDK 도 붙이지 않는다 — 부르는 곳이 넷뿐이다.
  - 필드 값은 로케일로 한 겹 감싸여 있다. 코드를 박아 두면 스페이스를 다른 로케일로 만든
    순간 전부 어긋나므로 **부팅 때 `/locales` 를 읽어 알아낸다.**
  - **부팅 로딩이 실패하면 계정 기능을 잠근다**(3번 재시도 뒤). 빈 채로 열면 가입해 둔
    사람들이 「없는 계정」이 되어 다시 가입하고, 같은 이메일로 줄이 둘 생긴다. 게스트는
    그때도 그대로 된다. 이것이 이 설계에서 제일 중요한 자리다.
  - 가입은 **밖에 먼저 쓰고 성공을 확인한 뒤에야** 메모리에 넣는다. 순서를 뒤집으면
    「가입됐다」고 말해 놓고 서버가 다시 뜨는 순간 없어진다. 있는지도 메모리만 믿지 않고
    한 번 더 물어본다 — 드문 동작이라 값이 싸고, 로딩이 반쯤 어긋났을 때를 막는다.
  - 전적은 **모았다가 흘려보낸다.** 열 명이 앉은 판이 끝나면 쓰기 열 건이 한꺼번에
    나가는데 CMA 는 초당 일곱 건쯤에서 막는다. 3초 모았다가 0.3초 간격으로 한 사람씩
    내보내고, 이메일로 모으므로 그 사이 같은 사람이 두 판 끝내도 마지막 값 한 번만 나간다.
    실패는 삼킨다 — 다음 판이 끝나면 그때 값이 다시 나가므로 늦게 맞으면 된다.
  - 콘텐츠 타입은 `account`, 필드는 `email`·`passwordHash`·`passwordSalt`·`nickname`·
    `wins`·`losses`. **이 이름이 곧 계약이다.** 환경변수는 `CONTENTFUL_SPACE_ID` ·
    `CONTENTFUL_ENVIRONMENT`(없으면 master) · `CONTENTFUL_MANAGEMENT_TOKEN` 이고,
    관리 토큰은 **쓰기 전권**이라 저장소에 두지 않고 Render 대시보드에서 넣는다.
  - **실물로 시험하지 못했다.** 자격증명이 없어 가짜 저장소로 걸음의 순서만 확인했다 —
    필드 이름·로케일 감싸기·버전 헤더가 실제로 맞는지는 처음 붙일 때 `logs/server.log` 로 본다.

- **혼자 해보기 — 화면 안에서 돈다**(2026-08-31에 서버에서 옮겼다). 봇 둘이 앉은 보통 판이고,

    모아 거기서만 가른다 — 화면이 「지금 어느 쪽인가」를 스무 군데에서 물으면 그중 하나를
    빠뜨리는 날이 온다. 이벤트는 양쪽을 다 듣는다. 연습판은 화면이 열려 있는 동안 열리고
    닫혀서, 하나를 골라두면 고르는 시점과 쓰는 시점이 어긋난다.

- **포커 방식이 여럿이다 — 지금은 텍사스 홀덤과 오마하**(2026-09-02).
  `shared/src/variants.ts` 한 파일이 그 자리다. **판(`engine`)은 어떤 포커인지 모른다** —
  「몇 장을 받고 · 언제 몇 장이 열리고 · 그중 무엇으로 손을 만드나 · 덱이 감당하는 정원」
  네 값을 표에서 건네받아 그대로 따른다. 그래서 변형을 더할 때 엔진에 손댈 곳이 없고,
  도전자·해결사 20장도 표 위에서 그대로 돈다.
  - **모드와는 층이 다르다.** 모드는 「어떤 카드가 걸리는가」, 방식은 「포커 자체의 규칙」이라
    둘은 곱해진다 — 오마하 + 프로 모드가 성립한다. 대기실 설정에서 방식이 모드보다 위에 선다.
  - **오마하는 홀 4장, 손에서 정확히 2장 + 공용에서 정확히 3장**이다. 이 제약이 전부라
    평가기를 따로 둔다(`evaluateOmaha`) — 텍사스의 「일곱 장 중 최선의 다섯 장」과 답이 다르다.
    보드에 플러시가 다 깔려 있어도 내 손에 같은 무늬 두 장이 없으면 내 플러시가 아니다.
  - **손을 읽는 자리가 넷인데 규칙은 한 벌이다.** 쇼다운·지문 스캔·「도주 운전사」·화면의
    조합 보기가 모두 표의 `evaluate`/`holding` 을 지난다. 하나라도 빠뜨리면 **스캔의 정답이
    실제 쇼다운과 어긋나** — 순서를 맞혔는데 실패하고, 이유가 화면 어디에도 안 나온다.
  - **프리플롭의 「지금 내 손」은 따로 센다.** 오마하에서 홀 넉 장을 통째로 보면 A 넉 장이
    포카드로 읽히는데, 쓸 수 없는 손이다. 두 장짜리 조합 중에서 고른다.
  - 🔴 **정원은 취향이 아니라 덱 52장의 산수다.** 최악의 판(「보안 카메라」로 홀 +1 →
    감지기가 그 홀을 통째로 재배분 → 「해커」 한 장)을 세어 방식마다 상한을 둔다 —
    텍사스 10명, **오마하 8명**. 덱이 비면 `draw()` 가 예외를 던지는데 **화면에는 아무 말도
    안 뜨고 판이 선다.** 방을 만들 때 막는 편이 낫다. 방식을 바꾸면 정원은 서버가 깎는다
    (해결사 자리를 승·패 수에 맞추는 `fitRounds` 와 같은 판단이다).
  - **스팟스**(2026-09-02)는 공용 아홉 장이 **3×3 격자**로 깔리고, **가로 한 줄씩** 열린다
    (`{0,3,6,9}`). 원작은 사람이 돌아가며 뒷면 한 장씩 뒤집는데 아홉 번이면 판 하나가
    너무 길어져서, 줄로 묶어 네 걸음에 끝낸다. 손은 **세 장 줄 하나 + 내 카드 넷**,
    일곱 장 중 다섯 장이다 — **두 줄에 걸친 다섯 장은 없다.** 원작의 3분할 팟
    (하이 · 로우 · 무늬 합산)은 쓰지 않는다. 더 갱은 팟을 나누는 게임이 아니라
    손을 약→강으로 줄 세우는 게임이라 로우와 무늬 점수를 얹을 자리가 없다.
    - **줄은 열린 카드가 아니라 자리로 정해진다**(`SPOTS_LINES`). 세는 차례와 그리는
      차례가 같아야 한다 — 갈리면 세로 줄이 화면에서는 세로가 아니게 된다.
    - **세로·대각은 셋째 줄이 열려야 비로소 선다.** 2라운드에는 가로 하나, 3라운드에는
      가로 둘뿐이다. 판이 마지막에 확 넓어지는 것이 이 변형의 맛이라, 덜 찬 줄을 미리
      세어 주지 않는다.
    - **모양은 세 군데에 같이 선다** — 테이블 · 쇼다운 모달 · 스캔 창. 셋이 `CommunityBoard`
      하나를 쓴다. 각자 그리게 두었더니 격자가 두 곳에서만 서고 모달에서는 한 줄로 펴졌다.
    - 정원은 **일곱**이다. 아홉 장이 판에 깔리는 만큼 자리가 준다.
    - **감지기(동작·레이저)는 첫 가로줄을 본다.** 「2라운드에 열린 카드」가 곧 첫 줄이라
      `community.slice(0, 3)` 이 그대로 뜻을 갖는다 — 텍사스의 플롭 자리와 같다.
  - **서클잭**(2026-09-02)은 공용 일곱 장이 **원으로** 깔리고, 원을 따라 **세 장씩** 열리다
    마지막 한 장으로 닫힌다(`{0,3,6,7}`). 손은 **홀 2장 + 원에서 붙어 있는 3장**이다.
    `[5,6,0]` 이 성립하는 것 — 끝과 끝이 이어지는 것 — 이 이 변형의 전부다.
    - **가운데 와일드카드는 옵션이다.** 켜면 마지막에 한 장이 더 열리고(`{0,3,6,8}`),
      **이웃 세 자리 중 아무 자리에나 끼워** 쓸 수 있다.
    - 🔴 **여기서 「와일드」는 숫자가 아니라 자리가 자유롭다는 뜻이다.** 카드는 7♦ 이면
      끝까지 7♦ 이고 모두에게 같은 한 장이다. 내 카드 두 장은 반드시 쓴다.
    - **하루 사이에 두 번 뒤집혔다**(2026-09-02, 둘 다 사용자가 실제 판에서 잡았다).
      ① 처음엔 「이웃 한 자리 대신」이었는데 이웃 셋이 이미 K 셋이면 와일드가 아무것도
      못 했다 → ② 「여섯 장 중 다섯 장」으로 열었더니 내 카드를 버릴 수 있게 되어
      손이 전반적으로 세지고 여러 사람이 같은 손을 잡았다(선언 놀이가 물러진다) →
      ③ **숫자를 자유롭게 둔 것이 애초의 잘못**이었다. 화면에 찍힌 7 이 뜻 없는 장식이
      되어, 보는 사람은 당연히 7 로 읽는다. 지금은 숫자가 그대로 읽히고 자리만 자유롭다.
      **「이웃 셋이 이미 세면 와일드가 할 일이 없다」는 그대로 남는다** — 알고 고른 대가다.
    - **「보안 카메라」로 홀이 석 장이어도 쓰는 것은 두 장**이다. 예전에는 석 장을 그대로
      넘겨 「5장이어야 한다: 6장 받음」으로 터졌다(같은 날 함께 고쳤다).
    - **계약에는 `circle` · `circleWild` 두 벌**이지만 **방 설정에는 한 줄과 체크칸**으로
      보인다. 목록에 「서클잭」이 둘 서면 무엇이 다른지 이름만으로 가려야 한다.
    - 공용이 적어 정원은 그대로 10이다.
  - 🔴 **바나나스플릿**(2026-09-03)만 층위가 다르다 — **공용 카드가 사람마다 다르다.**
    카드가 가운데가 아니라 **자리와 자리 사이**에 3장씩 놓이고, 각자 **자기 양옆 두 묶음
    6장 + 내 카드 2장, 여덟 장 중 다섯 장**을 쓴다. 이웃끼리는 한 묶음을 나눠 쓰지만
    테이블 전체가 같은 카드를 보는 것은 아니다.
    - **배열은 그대로 하나다.** 라운드마다 **묶음마다 한 장씩** 놓이므로, 인원이 N 이면
      묶음 g 는 `g` · `N+g` · `2N+g` 자리에 흩어져 있다(`bananaGroup`). 이 셈 덕분에
      `GameView.community` 를 쪼개지 않아도 됐다.
    - **계약이 두 군데 넓어졌다**(다른 넷은 한 글자도 안 바뀐다):
      `dealt(round, seats)` — 판이 인원과 함께 커지는 유일한 변형이라 고정 표를 함수로,
      `communityFor(공용, 자리, 인원)` — **엔진이 사람마다 잘라서 넘긴다.** 그래서
      평가기는 여전히 「내 카드 + 내가 쓸 수 있는 공용」만 본다.
    - **자르는 자리를 빠뜨리면 남의 묶음으로 답한다.** 쇼다운·지문 스캔·「도주 운전사」는
      엔진의 `communityOf`, 화면(지금 내 손·조합 보기·쇼다운)은 `usableCommunity` 를 지난다.
      쇼다운은 토큰 순으로 줄을 세우므로 `ShowdownEntry` 에 **자리 번호**를 따로 싣는다.
    - **「나」라고 적는 자리와 아래로 돌리는 자리는 다르다**(`me` · `focus`). 한 값으로
      묶어 두었더니 쇼다운에서 남을 짚어 판이 그쪽으로 돌 때 **그 사람 자리에 「나」가
      적혔다** — 돌아간 것이 아니라 내가 거기 있는 것처럼 읽혔다(2026-09-03).
    - **판은 원형이고 내 자리가 늘 아래**다(`board-banana`). 자리와 묶음이 번갈아 서고,
      내가 쓸 수 있는 두 묶음만 진하다 — 남의 묶음은 지우지 않고 흐리게 둔다(남의 손을
      어림하는 것이 이 게임이라 무엇이 깔렸는지는 보여야 한다). 같은 판이라도 사람마다
      다르게 돌아가 서지만 이웃 관계는 같다.
    - **정원 6.** 덱은 여유가 있고(최악 40장) **화면이 먼저 막는다** — 한 바퀴에 열두
      덩이가 서면 「내 양옆」이 눈에 안 들어온다.
  - **「보안 카메라」는 이제 「한 장 더」다.** 텍사스에서는 2 → 3 이라 룰북과 같고,
    오마하에서는 4 → 5 가 된다. 「정확히 두 장」은 그대로라 고를 폭만 넓어진다.
    카드 문구에서 「3장씩」을 뺐고, 「계산가」의 「두 장의 합」도 「받은 카드의 합」으로 고쳤다
    (코드는 원래부터 홀카드 전부를 더하고 있었다).
- **자동 확정**(2026-09-02). 모두가 토큰을 쥔 뒤 **15초**가 지나면 다 같이 확정되어 라운드가
  넘어간다. 아무도 누르지 않아 판이 서 있는 자리를 없애려는 것이다 — 한 사람이 잠깐
  자리를 비우면 나머지가 기다리는 것 말고 할 수 있는 일이 없었다.
  - **리버에서는 재지 않는다.** 마지막 선언 뒤가 곧 쇼다운이라 무를 자리가 없다.
    프리플롭·플롭·턴에서만 돈다.
  - **마지막 5초는 화면 한가운데 큰 숫자**로 센다(`.verdict--count`). 성공·실패와 같은
    자리·같은 크기지만 색은 갈라 두었다 — 금색이나 붉은색으로 두면 숫자가 뜨는 것만으로
    무슨 판정이 난 줄 안다. 그전 10초는 발밑 한 줄(「n초 뒤 자동 확정」)로만 알린다.
  - **누가 토큰을 옮기면 시계는 처음부터**다. 옮기는 동안 그 사람의 손이 비어 조건이
    깨지기 때문이고, 마음이 바뀐 사람에게 판단할 시간을 도로 주는 것이 맞다.
  - **시계는 판(`Game`)이 쥔다.** 서버는 예약해 두었다가 깨우기만 하고, 판이 「아직
    아니다」로 돌려보내면 남은 만큼 다시 잰다(`scheduleAutoConfirm`, 토큰 잠금 예약과 같은 꼴).
    화면에는 **시각이 아니라 남은 길이**(`autoConfirmIn`)를 보낸다 — 절대 시각을 보내면
    화면의 시계가 서버와 어긋난 만큼이 그대로 카운트다운에 실린다.
  - **혼자 해보기에서는 꺼 둔다**(`autoConfirmMs: 0`). 안내가 떠 있는 동안 봇은 멈추지만
    시계는 멈추지 않아, 읽는 사이에 라운드가 넘어간다.
- **소리**(2026-08-26). 효과음은 파일이 아니라 그 자리에서 만드는 파형이다(`sfx.ts`).
  칩 딸깍·딩·사이렌은 노이즈와 사인파에 엔벨로프를 씌운 것이라, 녹음을 구해 오는 것보다
  숫자 몇 개를 만지는 편이 빠르다 — 번들이 늘지 않고, 공개된 화면이라 늘 따라오던 출처
  문제도 없다. 스물여섯 갈래가 돈다.
  - **토큰은 내 것과 남의 것이 갈린다.** 한 번의 뺏기가 두 사람의 자리를 함께 바꾸므로
    「새로 쥔 쪽」에서만 울리고, 빈자리는 그 토큰이 중앙으로 돌아갔을 때에만, 곧 스스로
    내려놓았을 때에만 운다. 그러지 않으면 한 동작에 두 번 난다. 내 것을 뺏긴 경우에는
    뺏겼다는 소리가 이미 울리므로 남의 집는 소리를 건너뛴다. 남의 소리는 내 것보다 한참
    작다 — 열 명이 앉은 판에서 같은 크기로 울리면 정작 내 손이 묻힌다.
  - **쇼다운은 한 사람마다 반음씩 오른다.** 사슬이 이어지는 중임을 글자보다 먼저 알린다.
    금고·경보와 승리·패배를 따로 둔 것은 층위가 달라서다 — 저쪽은 판 하나의 결말이고
    이쪽은 여기서 자리를 뜬다는 뜻이라, 1.5초를 두고 뒤에 온다.
  - **단추는 클래스와 `aria-pressed` 로 갈린다.** 확정·나가기·취소·토글이 저마다 다르되
    컴포넌트는 한 줄도 고치지 않았다. 문서에서 한 번만 듣고 눌린 것이 무엇인지 보므로,
    새로 만드는 단추도 클래스만 맞으면 따라온다. 토큰과 잠긴 단추는 뺀다 — 앞의 것은
    자기 소리가 따로 있고, 뒤의 것은 눌러도 아무 일이 없는데 소리가 나면 눌린 줄 안다.
  - **배경음악은 받아 온 파일**이고 셋 다 CC0 다(만든 사람은 README 에 적어 두었다).
    화면에 부르는 이름을 곡 제목이 아니라 분위기(잠입·추리·재즈)로 둔 것은, 고르는 사람이
    곡을 아는 것이 아니라 분위기를 고르기 때문이다. 곡을 바꿀 때만 처음부터 시작하고
    크기를 만질 때는 흐르던 자리를 지킨다 — 매번 되감기면 듣던 데를 잃는다.
  - **크기는 `audio.ts` 한 곳에 모았다.** 효과음과 배경음악은 나는 방식이 전혀 다르지만
    사람이 만지는 손잡이는 하나여야 한다. 음소거를 크기 0 과 따로 둔 것은 되돌아올 자리
    때문이다 — 슬라이더를 내려 끄면 다시 켤 때 얼마였는지 잊는다.
  - 브라우저는 사람이 한 번 누르기 전까지 소리를 내주지 않는다. 그래서 배경음악의 첫
    재생은 거의 언제나 거절당하고, 그것을 실패로 보지 않고 첫 손짓을 기다렸다가 다시 건다.

## 겪어서 알게 된 것 (다시 밟지 말 것)

**공개 여부는 「공개할 단계」를 적는다. 「아닌 단계」를 적지 않는다.** 판 상태의 홀카드를
`phase !== 'picking'` 이면 공개로 두었는데, 나중에 딜 직후 단계(`setup`)가 생기면서 그 자리에
딸려 들어갔다 — 「조율가」·「사기꾼」이 걸린 판은 넘길 카드를 고르는 동안 **전원의 홀카드가
모두에게(관전자에게도) 나갔다**(2026-09-03). 기본값이 「공개」면 단계가 하나 늘 때마다 같은
일이 난다. 화면에도 같은 모양의 조건이 한 벌 더 있어서 그대로 앞면으로 그려졌다 —
**서버와 화면이 같은 실수를 나눠 갖고 있으면 유출이 눈에 보이는 데까지 간다.**

**남의 카드를 그리는 길 자체를 두지 않는다.** 위 유출을 고치면서 자리 카드를 장식으로
바꿨다(2026-09-03). 쥔 장수만큼 뒷면을 세우고 앞면은 그리지 않는다. 공개되는 두 순간
(스캔·쇼다운)은 각각 제 창이 화면을 덮고 필요한 카드를 그 안에 다시 그리므로, 자리에서
뒤집을 일이 없다. 서버가 또 새더라도 화면에는 안 뜬다.

**방을 접을 때는 방까지 지운다.** 재경기 거절이 판(`games`)만 지우고 방은 `playing` 인 채로
남겼다. 그러면 `room:closed` 를 놓친 사람 — 새로고침했거나, 잠깐 끊겼다 붙었거나, 목록에서
그 방을 다시 누른 사람 — 이 **방은 있고 판만 없는** 자리에 떨어진다. 대기실로 돌려보내지도
(단계가 lobby 가 아니라서), 판을 보내주지도 못해 화면이 「테이블을 차리는 중」에서 영영
멈춘다(2026-09-03). `store.closeRoom()` 이 그 자리다.

**`overflow: hidden` 은 그 안의 absolute 도 자른다.** 감정 말풍선을 자리 이름 칸에 얹었더니
남의 자리에서만 안 보였다 — 그 칸에 긴 이름을 자르려고 `overflow: hidden` 이 걸려 있었다.
내 자리에는 없어서 거기서만 보였고, 그래서 「카드에 가려진 것」으로 한참 오해했다.
`elementFromPoint` 로 히트 테스트할 때는 **`pointer-events: none` 인 요소가 빠진다** —
가려진 것과 클릭 대상이 아닌 것을 구별하려면 잠시 켜고 재야 한다.

**떠 있는 것을 갈아치우지 말고 차례를 지킨다.** 감정표현이 연달아 오면 그림만 바꿨는데,
그러면 두 번 누른 것이 한 번 누른 것처럼 읽힌다. 앞의 것이 다 내려간 뒤에 올라오게 했다
(`EMOTE_EXIT_MS`). 서버에서 오는 사건은 렌더 밖이라 콜백 안의 상태가 낡아 있다 —
「지금 무엇이 떠 있나」를 물으려면 `ref` 거울이 하나 필요하다.

**값이 걸린 저장은 실패를 삼키지 않는다.** 전적은 뒤에서 보내고 실패를 버려도 되지만
(다음 판에 다시 나간다), 구매는 골드가 깎이므로 **밖에 쓰고 성공을 확인한 뒤에야** 메모리에
넣는다. 순서를 뒤집으면 「구매 완료」라고 말해 놓고 서버가 다시 뜨는 순간 골드만 깎인 채로
남는다.

**그 «밖에 쓰는 동안»이 열려 있었다**(2026-09-04에 닫음). `buy` 와 `equip` 은 값을 읽고
→ 밖에 쓰고 → 통째로 덮어쓴다. 같은 계정을 **두 창에** 열면 나중에 끝난 쪽이 먼저 끝난
쪽을 지웠다 — 「구매 완료」라고 답해 놓고 아이템도 골드도 없는 자리가 났다. 화면에도
잠금이 있지만 **잠금은 그 창 안에서만 보인다.** 지금은 계정 이메일마다 약속 사슬을 두고
둘을 거기 태운다(`Accounts.queue`). **판정을 사슬 안으로 옮긴 것이 요점이다** — 줄 밖에서
읽은 값은 차례가 올 때쯤 낡아 있다. 테스트는 저장소를 **일부러 느리게** 준다. 즉시 끝나는
저장소로는 재현되지 않고, `.env` 없는 로컬은 저장소가 아예 없어 이 틈도 없다.

**Contentful 항목은 계속 초안(draft)이다.** 발행(publish)을 부르지 않기 때문이고 **일부러
그렇다** — 읽기도 관리 API(CMA)로 하므로 초안이 그대로 돌아온다. 대시보드에서 「미발행」으로
보이는 것은 정상이다(`accountStore.ts` 머리말에 적혀 있다).

**로컬 dev 서버는 실제 Contentful 에 붙어 있다.** `npm run dev:server` 가 `--env-file-if-exists`
로 `.env` 를 읽는다. 여기서 시험 가입하면 **사용자의 진짜 스페이스에 계정 줄이 남는다.**
계정을 건드리는 시험은 **자격증명 없는 서버를 따로 띄워** 한다 — 그러면 계정이 메모리에만
남는다(로그에 `계정 N개를 읽었다` 가 있으면 저장소가 붙어 있는 것이다):

```bash
PORT=3002 CORS_ORIGINS=http://localhost:5175 node --watch server/src/index.ts
VITE_SOCKET_URL=http://localhost:3002 npx vite web --port 5175 --strictPort
```

`--watch` 를 빠뜨리면 **소스를 고쳐도 옛 코드가 계속 돈다.** 새 이벤트가 응답조차 없어서
한참 헤맸다. 대신 `shared` 를 고칠 때마다 서버가 다시 떠 **방이 사라진다.**

**CSS 미디어 쿼리는 파일 끝에 모은다.** 기본 규칙보다 앞에 두면 우선순위가 같아
나중에 오는 기본 규칙이 이긴다. 오류 없이 조용히 안 먹어서 두 번 헤맸다
(모바일 캐러셀, 로고 크기). `styles.css` · `game.css` 둘 다 끝에 모아 두었다.

**등장 애니메이션의 fill 은 `backwards` 다.** `both` 로 두면 끝난 뒤에도 `transform` 을
붙들어, 강조 같은 다른 변형이 먹지 않는다. 그것 때문에 강조를 애니메이션으로 만들었다가
강조가 꺼질 때 카드가 다시 날아드는 버그가 났다.

**소켓 테스트는 「다음 이벤트 하나」로 기다리면 안 된다.** 직전 동작이 만든 브로드캐스트를
잘못 집는다. 조건으로 기다리거나(`until`), 각자가 받은 상태를 모아 두고 되짚는다(`waitState`).
같은 실수를 두 번 했다.

**폭을 정하지 않은 부모 안에서 `width: 100%` 는 아주 좁게 잡힌다.** 드로어가 그랬다.

**한 파일을 짧은 사이에 두 번 쓰면 Vite 가 중간 상태를 캐시한다.** 「쓰는 곳은 있는데
정의가 없는」 코드가 브라우저로 가서 `X is not defined` 가 났다. 디스크의 파일은 멀쩡하고
`npm run build --workspace @the-gang/web` 도 통과해서 한참 헤맸다. 편집이 여러 번 나뉘었으면 마지막에 `touch` 한다.

**인자 없는 `socket.off('연결')` 은 그 이벤트를 듣던 모두를 떼어낸다.** 게임 화면을
벗어날 때 그것을 불러, 연결 표시등이 등록해 둔 것까지 함께 날아갔다. 그 뒤로는 소켓이
멀쩡히 재접속해도 화면이 「끊김」인 채로 남는다. 증상이 「재접속이 안 된다」로 보여서
소켓을 한참 의심했는데, 실제로는 이미 붙어 있었다. 뗄 때는 핸들러를 지정한다.

**서버 상태 객체를 useEffect 의존성에 넣지 않는다.** 상태는 누가 토큰만 집어도 새로 오므로
매번 정리 함수가 돌아 타이머가 취소된다. 키 문자열 하나에만 맨다.

**은닉 정보는 통로를 하나로 묶는다.** 공개 상태(`GameView`)에는 쇼다운 전까지 누구의
홀카드도 없다 — 본인 것조차 없다. 스캔 중 지목된 사람의 카드도 답이 정해질 때까지
서버 밖으로 나가지 않는다. 미리 보내고 화면에서만 가리면 통신을 열어보는 것으로 답을 안다.

**색은 두 벌이지만 물건은 한 벌이다.** 밝은 쪽을 만들 때 카드·토큰·초록 펠트까지 뒤집으면
안 된다 — 조명이 바뀐다고 트럼프가 검게 변하지는 않는다. 그래서 `--felt` 는 두 테마가 같은 값을
쓰고, 로비 목록의 바탕은 `--surface` 로 갈라두었다. 처음에 둘을 한 토큰으로 두었다가
밝은 쪽에서 초록 위에 검은 글씨가 났다.

**테마는 화면이 그려지기 전에 정해야 한다.** React 가 뜬 뒤에 `data-theme` 을 붙이면
첫 한 칠이 어두운 채로 나왔다가 밝아진다. `index.html` 의 인라인 스크립트가 먼저 정한다.

**손패가 바뀌는 경로를 빠뜨리기 쉽다.** 감지기가 카드를 갈아엎어도 새 손패를 보내지 않아
화면에 옛 카드가 남았다. 지금은 라운드가 넘어갈 때 손패를 함께 보낸다.

**보이는 수와 판정하는 수가 다르면 화면이 거짓말을 한다.** 방 목록은 접속 중인 사람을
셌고, 입장 판정은 자리를 셌다. 끊긴 사람의 자리는 유예 동안 지켜지므로 둘이 갈린다 —
목록이 「2 / 3」이라 말해 놓고 눌러 보면 「정원이 찼습니다」였다. 지금은 목록도 자리를
세고, 몇이 비어 있는지를 따로 알려준다(`awayCount`).

**끊김은 즉시 알려지지 않는다.** 주소창을 고쳐 치면 새로고침이라 소켓이 끊기지만,
서버가 알아채는 데 최대 45초가 걸린다(핑 주기 25초 + 대기 20초). 그동안 그 사람은
「접속 중」인 채로 자리를 차지하고 있다. 「한동안 지나야 되더라」는 대개 이 시간이다.

**정원이 찼어도 내 자리는 열려 있어야 한다.** 서버는 정원을 보기 전에 재접속으로
받아주는데, 목록은 그 방이 내 자리인지 몰라 함께 잠갔다. 새로고침한 창은 자기가 어디
앉아 있었는지도 잊으므로 서버에 묻는다(`room:where`). 소켓이 아니라 playerId 로 묻는
것이 핵심이다 — 그 창의 소켓은 아직 어느 사람과도 매여 있지 않다.

**우리가 부른 `history.back()` 도 popstate 로 돌아온다.** 그것을 사람이 누른 것으로 받으면
엉뚱한 일이 벌어진다. 개발 모드는 효과를 두 번 실행하므로 「쌓기 → 걷어내기 → 다시 쌓기」가
일어나는데, 걷어내며 부른 back 이 새 가드에 잡혀 **방을 만들자마자 나가졌다.** 스스로 부른
back 은 세어 두었다가 그 신호를 흘려보낸다(`web/src/lib/back.ts` 의 `unwinding`).
세는 자리는 훅이 아니라 파일이다 — 걷어내는 쪽과 받는 쪽이 서로 다른 가드일 수 있다.

**같은 특이도면 나중에 오는 규칙이 이긴다 — 미디어 쿼리만의 이야기가 아니다.**
스팟스의 `--grid3` 세 벌을 한자리에 모아 두었는데, 그중 둘이 자기 기본 규칙보다 **앞에**
놓였다. 클래스 하나 대 클래스 하나라 특이도가 같고, 뒤에 오는 `display: flex` 가 이겼다 —
테이블만 격자로 서고 쇼다운 모달과 스캔 창은 한 줄로 펴졌다. 오류도 경고도 없다.
지금은 **덧쓰는 규칙을 저마다 자기 기본 규칙 바로 뒤에** 둔다. 애초에 세 군데가 각자
그리고 있던 것이 화근이라, 공용 카드는 `CommunityBoard` 하나로 모았다.

**층(z-index)은 표에 이름으로 둔다.** `web/src/styles.css` 의 `:root` 에 `--z-bar` 부터
`--z-tip` 까지 열한 층이 아래에서 위로 적혀 있고, **숫자를 직접 쓰지 않는다**. 각자 자기
자리에서 숫자를 고르면 「무엇이 무엇을 덮는가」가 어디에도 없게 되어, 실제로 두 번 났다 —
대화창 위를 토큰이 가로질러 날았고(그래서 비행은 20 이 아니라 `--z-verdict`), 모바일 확정
바가 `--z-bar` 라서 그 위로 토큰이 지나갔다. **CSS 밖에 하나 남아 있다** —
`useTokenFlight.ts` 의 비행 층. 표를 고치면 그 줄도 함께 봐야 한다.
요소 안에서만 앞뒤를 가리는 값(카드 강조 · 드로어 탭)은 표에 들지 않는다.

**`disabled` 인 버튼에는 마우스 이벤트가 오지 않는다.** 설정의 카드 칩이 그랬다 —
방장이 아닌 사람은 짚어도 설명이 하나도 안 뜨고 금지 표시만 났다(2026-09-03).
브라우저가 disabled 요소에 이벤트를 아예 보내지 않아서, 붙여 둔 손짓이 통째로 죽어 있었다.
지금은 `aria-disabled` 로 같은 뜻을 전하고 누름만 막는다. 스타일도 `:disabled` 가 아니라
`[aria-disabled='true']` 를 본다.

**모듈을 갈아엎으면 문서에 붙은 리스너가 옛 것을 붙든다.** 소리의 저장 로직을 `sfx.ts` 에서
`audio.ts` 로 들어냈는데, 단추 소리를 듣는 리스너는 `document` 에 붙어 있어서 옛 모듈의
함수를 그대로 들고 있었다 — 음소거를 눌러도 단추 소리가 났다. 코드는 멀쩡하고 새로고침하면
사라진다. 인자 없는 `socket.off` 나 Vite 의 중간 상태 캐시와 같은 계열이다.

## 남은 일

**1. 돌려보며 드러나는 것 줍기**

친구들에게 뿌렸고, 버그·개선사항은 구글 시트(또는 폼)로 받는다. 칸은 넷이다 —
이름 · 내용 · 분류(버그/불편/제안) · 화면(로비/방/게임/결과).

**무료 요금제는 15분 무트래픽이면 잠들고, 깨어날 때 방이 전부 사라진다.** 첫 접속자가
1~2분 기다리는 자리는 `ServerGate` 가 덮는다. 사람들을 부르기 전에 `/healthz` 를 한 번
열어 깨워두면 그 기다림이 없다. 리전은 싱가포르다. **계정은 이제 그때도 살아남는다** —
Contentful 에 한 벌 있기 때문이다. 혼자 해보기도 서버 없이 열린다.

**2. 눈으로 확인된 것과 아직 못 본 것**

**에이전트가 크롬을 직접 띄운다**(2026-09-03부터). 예전에는 확장이 붙지 않아 레이아웃·
애니메이션을 전부 사용자가 보고 알려줘야 했는데, 이제 직접 열어 누르고 재고 고친다.
이번 차수의 화면 결함은 대부분 그렇게 잡았다 — 만들고 나서 보면 거의 늘 무언가 어긋나 있다.
**브라우저로 여는 주소는 `localhost`/`127.0.0.1`/`*.lvh.me` 뿐이다**(운영 화면·깃허브 등
그 밖의 사이트는 열기 전에 무엇을·왜 여는지 말하고 허락을 받는다).

**2026-09-03~04 배포분은 화면까지 확인됐다.** 해결사 투표(만장일치·표 갈림·남이 뽑힘) ·
코스메틱 슬롯 넷(라이트·다크 · 모바일 414px) · 상점에서 구매·장착 · 감정표현(로비·판) ·
바나나스플릿 겹친 카드 · 채팅 미리보기.

  아래로 오는 것, 라운드마다 한 장씩 느는 것까지. 겹친 카드의 숫자·무늬가 좁은 화면에서
  안 보이던 것을 그때 잡았다.

  **마지막 규칙으로 고친 뒤로는 못 봤다** — 가운데 카드가 7♦ 이면 끝까지 7♦ 로 셈해지는지,
  이웃 셋의 아무 자리에나 끼워지는지.

  10초쯤 발밑 줄이 줄다가 5부터 큰 숫자가 뜨는지, 0에서 라운드가 넘어가는지, **리버에서는
  아무것도 안 뜨는지**, 중간에 토큰을 옮기면 15초로 되감기는지.

## 대화하며 정해진 작업 방식

- 화면·디자인 결정은 옵션을 내고 사용자 확인을 받는다.
- **push 는 넷을 이 차례로.** ① 사용자 확인 → ② `pull`·`merge` → ③ 빌드·시험 검증 →
  ④ push. 순서를 바꾸거나 건너뛰지 않는다. **커밋은 확인 없이 바로 한다 — 갈리는 것은
  push 하나다.** 얹을 때는 `merge`(⛔ `rebase` — 남의 미푸시 커밋 해시를 갈아 치운다),
  얹은 뒤 다시 빌드하고, **push 직전에 `fetch` 를 한 번 더** 한다. 뒤처진 것이 0이어도
  그 사실을 확인하는 `fetch` 는 생략하지 않는다.
- **`/healthz` 의 `rooms` 를 push 전에 본다.** 서버가 재시작되면 떠 있던 방이 전부
  사라진다. 사람이 하고 있으면 기다린다.
- 서버 코드가 바뀌면 재시작이 필요하고 **그때 방이 전부 사라진다.** 사용자가 게임 중일 수
  있으니 재시작 전에 알리거나 판이 끝나기를 기다린다.
- 커밋을 나눌 때 **새 파일이 어느 쪽에 들어가는지 본다.** `shared/src/emotes.ts` 를 첫
  커밋에서 빠뜨려 그 커밋만으로는 빌드가 안 됐다 — 푸시 전이라 두 커밋을 다시 묶어 고쳤다.
- **같은 저장소를 두 사람(세션)이 함께 쓴 적이 있다.** `git add -A` 는 남의 작업 중인 파일까지
  쓸어담는다 — 실제로 효과음 작업이 남의 커밋에 섞여 들어갔다. 내가 고친 파일만 지정해서
  add 하고, push 전에는 `git log origin/master..HEAD` 로 남의 커밋이 얹혔는지 본다.
- **화면 층은 만들고 나서 직접 본다.** 크롬이 붙으므로 열어서 누르고 재고 고친다 —
  만들어 놓고 보면 거의 늘 무언가 어긋나 있다(이번 차수의 화면 결함은 전부 그렇게 나왔다).
  스크린샷으로 판단이 안 되는 것(움직임·순간)은 DOM 을 재거나 잠시 고정해 놓고 본다.
- **화면을 고칠 때는 회귀 테스트를 서버 쪽에 남긴다.** 화면에는 러너가 없으므로, 규칙으로
  옮길 수 있는 부분(유출·좀비 방 같은 것)은 서버 테스트로 못박고 **옛 코드에서 실제로
  실패하는지까지 확인한다.** `git stash` 로 되돌리면 테스트도 함께 사라지니, 고친 파일만
  잠깐 되돌려 재야 한다.
- **한 건 고치면 그 자리에서 빌드하고 테스트한 뒤 다음으로 넘어간다.** 여러 건을 겹쳐
  고치면 깨진 것이 어느 변경 때문인지 가려내는 데 더 든다.
- 한 파일을 짧은 사이에 두 번 쓰면 Vite 가 중간 상태를 캐시한다. 편집이 나뉘었으면
  마지막에 `touch` 한다.
- 원인을 추측하지 말고 재현부터 한다. 새로고침 버그는 서버에 직접 쳐 보고 서버가
  정상임을 확인한 뒤 화면으로 좁혔다.
