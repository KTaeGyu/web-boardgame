# 더 갱 웹 — 지금 상태와 다음 할 일

보드게임 **더 갱**(협력 포커)의 웹 구현. 회사 업무가 아니라 개인 프로젝트다.
이 문서는 지금의 스냅샷이다. 설계 근거는 `README.md` 「정해진 것」, 카드 규칙 전문은
`docs/도전자-해결사-카드.md` 가 정본이고, 여기서는 **어디까지 왔고 무엇이 남았는지**만 다룬다.

## 무엇을 만들고 있나

3~10인이 브라우저에서 함께 하는 협력 포커. 텍사스 홀덤과 같은 진행이지만 베팅 대신
**토큰**을 집어 「내 손이 상대적으로 몇 번째로 센가」를 선언한다. 카드 이야기는 금지 —
토큰이 유일한 언어다. 마지막 라운드 토큰 순서대로 공개해 약→강이면 금고를 열고,
틀리면 경보가 울린다. 금고 3개면 승리, 경보 3개면 패배.

**게임 자체는 규칙까지 완성됐고, 2026-08-25 에 배포했다.** 친구들이 실제로 하고 있다.
지금 남은 것은 「돌려보며 드러나는 것」을 줍는 일이다.

## 어디에 사는가

| 무엇 | 주소 |
|------|------|
| 화면 | https://web-boardgame.vercel.app |
| 소켓 서버 | https://web-boardgame-server.onrender.com |
| 저장소 | https://github.com/KTaeGyu/web-boardgame (`master`) |

**`master` 에 push 하면 그대로 배포된다.** Vercel 은 화면을, Render 는 서버를 새로 세운다.
서버가 재시작되면 **떠 있던 방이 전부 사라지므로**, 올리기 전에 `/healthz` 의 `rooms` 를
본다. 절차와 함정은 `docs/배포.md` 가 정본이다.

## 지금 돌려보려면

```bash
cd 개인프로젝트/the-gang
npm install
npm test              # 233개
npm run typecheck
npm run dev:server    # 소켓 서버 :3001
npm run dev:web       # 화면 http://localhost:5173
```

둘 다 띄워야 동작한다. 여러 명을 흉내내려면 **새 탭이 아니라 새 창**(또는 시크릿 창)으로 연다 —
정체성이 `sessionStorage` 에 있어서 탭마다 다른 사람이 되지만, 같은 창의 새 탭은 세션을 물려받을 수 있다.

**서버를 다시 띄우면 방이 전부 사라진다.** 상태가 전부 메모리에 있기 때문이다.
그 상태에서 게임 화면을 새로고침하면 「방이 사라졌습니다」가 뜨고 목록으로 돌아간다.

## 구조

| 폴더 | 역할 | 배포 |
|------|------|------|
| `shared/` | 카드·핸드 평가·쇼다운 판정·프로토콜. 서버와 웹이 함께 쓴다 | — |
| `server/` | Socket.IO 게임 서버. 상태는 전부 메모리 | Render |
| `web/` | React 클라이언트 (Vite) | Vercel |

**DB 는 쓰지 않는다.** 방보다 오래 사는 데이터가 하나도 없어서 뺄 수 있었다.
계정·전적처럼 서버 재시작을 넘겨야 하는 것을 넣으려면 저장소가 따라온다.
(2026-08-25 에 「지금은 그대로 둔다」로 닫혔다. 필요해지면 비밀번호 없이
`localStorage` 기기 토큰이 제일 싸게 붙는다.)

Node 22.18+ 의 네이티브 TS 실행에 기대어 `shared` 와 `server` 는 **빌드 단계가 없다**.
그래서 `enum` 을 쓸 수 없다(strip-only). const 객체 + union 타입으로 쓰고,
tsconfig 의 `erasableSyntaxOnly` 가 실수를 잡는다.

## 규칙이 어디에 있나

- `shared/src/handEval.ts` — 7장 중 최선의 5장. 사전식으로 비교 가능한 `score` 배열을 준다.
  우열뿐 아니라 **완전히 같음**까지 구분해야 해서 족보 이름이 아니라 배열이다.
- `shared/src/showdown.ts` — 「앞사람보다 같거나 강하면 통과」. 등호를 허용하는 것만으로
  룰북의 true tie 가 자연히 풀린다. 「근육」이 걸리면 같은 족보끼리의 우열이 뒤집힌다.
- `server/src/rooms.ts` — 방. 소켓도 시계도 모른다. 시간을 주입받아 재접속 유예를
  타이머 없이 테스트한다.
- `server/src/game.ts` — 한 판의 진행과 **걸린 카드가 무엇을 하는가**.
- `server/src/extras.ts` — **어느 판에 무엇이 걸리는가**(모드별 뽑기). 규칙과 갈라두어야
  각각 따로 검증된다.
- `server/src/socket.ts` — 배선만. 누가 무엇을 듣는지.

## 붙어 있는 것

**카드 20장 전부**(도전자 10 · 해결사 10)와 **모드 5종**이 돈다.
모드는 기본 · 고급 · 프로 · 마스터 시프 + **직접 고르기**(원작에 없는 모드, 방장이 카드를 고른다).

화면은 메인(`/`) · 방 목록(`/rooms`) · 방(`/rooms/:code`) · 게임(`/rooms/:code/game`).

카드를 온라인으로 옮기며 생긴 장치가 셋이다.

- **드로어** — 이번 판에 걸린 카드가 화면 옆에 카드 모양(5:7)으로 붙어 있다. 마우스를 올리면
  설명이 커서 옆에 뜨고, 누르면 뒤집혀 설명·결과·쪽지가 나온다. 해결사는 뒷면에서 쓴다.
- **쪽지** — 카드가 나에게만 알려주는 것은 `game:note` 로 그 사람 소켓에만 간다.
  도착하면 한 번 뜨고, 뒤에는 드로어에서 다시 본다.
- **해결사 배치표** — 「직접 고르기」에서 해결사는 고르는 것이 아니라 **판을 지정한다.**
  가로 한 줄이 카드, 세로 한 칸이 판(최대 5판)이다. 세로로는 하나만 서지만(한 판에 한 장)
  가로로는 여럿이어도 된다 — 같은 카드를 1판부터 5판까지 내리 세워도 된다. 「썼는가」가
  판마다 새로 시작하기 때문이다. 빈칸도 뜻이 있어서, 다섯째 칸에만 찍으면 앞의 네 판은
  해결사 없이 지나간다. 이렇게 판별로 짤 수 있다는 것이 다른 모드와 갈리는 지점이다.
- **화이트/다크** — 오른쪽 위 단추 하나로 바꾼다. 한 번도 누르지 않았으면 기기 설정을 따르고,
  누른 뒤에는 그 뜻이 이긴다(`localStorage`). 어느 쪽인지는 늘 `<html data-theme>` 에 적혀 있다.
- **다 같이 하는 단계** — 정해진 시점에 전원이 한 번씩 움직인다. 「조율가」·「사기꾼」은 딜 직후,
  스캔(「망막」·「지문」)은 마지막 사람이 공개되기 전. 스캔은 표가 서로 보여서 말 없이도
  만장일치로 옮겨간다. 둘 다 걸리면 둘 다 맞혀야 한다.

## 겪어서 알게 된 것 (다시 밟지 말 것)

**CSS 미디어 쿼리는 파일 끝에 모은다.** 기본 규칙보다 앞에 두면 우선순위가 같아
나중에 오는 기본 규칙이 이긴다. 오류 없이 조용히 안 먹어서 두 번 헤맸다
(모바일 캐러셀, 로고 크기). `styles.css` · `game.css` 둘 다 끝에 모아 두었다.

**등장 애니메이션의 fill 은 `backwards` 다.** `both` 로 두면 끝난 뒤에도 `transform` 을
붙들어, 강조 같은 다른 변형이 먹지 않는다. 그것 때문에 강조를 애니메이션으로 만들었다가
강조가 꺼질 때 카드가 다시 날아드는 버그가 났다.

**소켓 테스트는 「다음 이벤트 하나」로 기다리면 안 된다.** 직전 동작이 만든 브로드캐스트를
잘못 집는다. 조건으로 기다리거나(`until`), 각자가 받은 상태를 모아 두고 되짚는다(`waitState`).
같은 실수를 두 번 했다.

**폭을 정하지 않은 부모 안에서 `width: 100%` 는 아주 좁게 잡힌다.** 드로어가 그랬다.

**인자 없는 `socket.off('연결')` 은 그 이벤트를 듣던 모두를 떼어낸다.** 게임 화면을
벗어날 때 그것을 불러, 연결 표시등이 등록해 둔 것까지 함께 날아갔다. 그 뒤로는 소켓이
멀쩡히 재접속해도 화면이 「끊김」인 채로 남는다. 증상이 「재접속이 안 된다」로 보여서
소켓을 한참 의심했는데, 실제로는 이미 붙어 있었다. 뗄 때는 핸들러를 지정한다.

**서버 상태 객체를 useEffect 의존성에 넣지 않는다.** 상태는 누가 토큰만 집어도 새로 오므로
매번 정리 함수가 돌아 타이머가 취소된다. 키 문자열 하나에만 맨다.

**은닉 정보는 통로를 하나로 묶는다.** 공개 상태(`GameView`)에는 쇼다운 전까지 누구의
홀카드도 없다 — 본인 것조차 없다. 스캔 중 지목된 사람의 카드도 답이 정해질 때까지
서버 밖으로 나가지 않는다. 미리 보내고 화면에서만 가리면 통신을 열어보는 것으로 답을 안다.

**색은 두 벌이지만 물건은 한 벌이다.** 밝은 쪽을 만들 때 카드·토큰·초록 펠트까지 뒤집으면
안 된다 — 조명이 바뀐다고 트럼프가 검게 변하지는 않는다. 그래서 `--felt` 는 두 테마가 같은 값을
쓰고, 로비 목록의 바탕은 `--surface` 로 갈라두었다. 처음에 둘을 한 토큰으로 두었다가
밝은 쪽에서 초록 위에 검은 글씨가 났다.

**테마는 화면이 그려지기 전에 정해야 한다.** React 가 뜬 뒤에 `data-theme` 을 붙이면
첫 한 칠이 어두운 채로 나왔다가 밝아진다. `index.html` 의 인라인 스크립트가 먼저 정한다.

**손패가 바뀌는 경로를 빠뜨리기 쉽다.** 감지기가 카드를 갈아엎어도 새 손패를 보내지 않아
화면에 옛 카드가 남았다. 지금은 라운드가 넘어갈 때 손패를 함께 보낸다.

## 남은 일

**1. 돌려보며 드러나는 것 줍기**

친구들에게 뿌렸고, 버그·개선사항은 구글 시트(또는 폼)로 받는다. 칸은 넷이다 —
이름 · 내용 · 분류(버그/불편/제안) · 화면(로비/방/게임/결과). 그 이상은 미리 파두지 않는다.
버그가 실제로 올라오면 그 줄에서 되물으면 된다.

배포 자체는 끝났다(2026-08-25). **무료 요금제는 15분 무트래픽이면 잠들고, 깨어날 때 방이
전부 사라진다.** 첫 접속자가 1~2분 기다리는 자리는 `ServerGate` 가 덮는다. 리전은 싱가포르다.

**2. 눈으로 확인되지 않은 것**

브라우저 확장이 이 환경에서 연결되지 않아, **화면을 직접 클릭해 본 적이 없다.**
테스트와 빌드는 통과하지만 레이아웃·애니메이션은 사용자 확인에 의존해 왔다.
특히 최근에 만든 것들이 검증이 얕다 — 카드 고르기 칩의 길게 누르기, 딜 직후 단계 모달,
버리기 모달, 스캔 모달 둘이 함께 뜰 때. **밝은 쪽은 아직 아무도 본 적이 없다** —
게임 화면(펠트 위의 카드·토큰·결과 글자)이 특히 확인이 필요하다.

**3. 다듬을 거리 (급하지 않음)**

- 해결사를 「먼저 누른 사람이 쓴다」로 두었다. 원작은 다 같이 정하는 것이라,
  제안·동의 절차를 넣을 여지가 있다.
- 「직접 고르기」에서 해결사는 판을 지정한다(배치표). 한 판에 두 장이 함께 걸리게 하려면
  사용 상태·딜 직후 단계·드로어를 여러 장 기준으로 다시 짜야 한다.
- 채팅은 없다. 원작의 「카드 이야기 금지」와 맞물려 지금은 없는 편이 규칙에 맞다.

## 대화하며 정해진 작업 방식

- 화면·디자인 결정은 옵션을 내고 사용자 확인을 받는다.
- 서버 코드가 바뀌면 재시작이 필요하고 **그때 방이 전부 사라진다.** 사용자가 게임 중일 수
  있으니 재시작 전에 알리거나 판이 끝나기를 기다린다.
- 커밋 메시지에 모델 attribution 을 넣지 않는다.
- 원인을 추측하지 말고 재현부터 한다. 새로고침 버그는 서버에 직접 쳐 보고 서버가
  정상임을 확인한 뒤 화면으로 좁혔다.
