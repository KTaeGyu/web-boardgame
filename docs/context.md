# 더 갱 웹 — 지금 상태와 다음 할 일

보드게임 **더 갱**(협력 포커)의 웹 구현. 회사 업무가 아니라 개인 프로젝트다.
이 문서는 지금의 스냅샷이다. 설계 근거는 `README.md` 「정해진 것」, 카드 규칙 전문은
`docs/도전자-해결사-카드.md` 가 정본이고, 여기서는 **어디까지 왔고 무엇이 남았는지**만 다룬다.

## 무엇을 만들고 있나

3~10인이 브라우저에서 함께 하는 협력 포커. 텍사스 홀덤과 같은 진행이지만 베팅 대신
**토큰**을 집어 「내 손이 상대적으로 몇 번째로 센가」를 선언한다. 카드 이야기는 금지 —
토큰이 유일한 언어다. 마지막 라운드 토큰 순서대로 공개해 약→강이면 금고를 열고,
틀리면 경보가 울린다. 금고 3개면 승리, 경보 3개면 패배.

**게임은 규칙까지 완성됐고 돌아가고 있다.** 첫 배포가 2026-08-25, 두 번째가 2026-08-26 이다.
두 번째에 29개 커밋이 한꺼번에 나갔다 — 토큰 무르기, 뒤로가기, 모바일 시트, 스캔 창의 판,
직접 고르기의 새 규칙, 소리. 지금 남은 것은 「돌려보며 드러나는 것」을 줍는 일이다.

서버가 재시작되면 **떠 있던 방이 전부 사라지므로**, 올리기 전에 `/healthz` 의 `rooms` 를
본다. 절차와 함정은 `docs/배포.md` 가 정본이다.

## 지금 돌려보려면

```bash
cd 개인프로젝트/the-gang
npm install
npm test              # 319개
npm run typecheck
npm run dev:server    # 소켓 서버 :3001
npm run dev:web       # 화면 http://localhost:5173
```

둘 다 띄워야 동작한다. 여러 명을 흉내내려면 **새 탭이 아니라 새 창**(또는 시크릿 창)으로 연다 —
정체성이 `sessionStorage` 에 있어서 탭마다 다른 사람이 되지만, 같은 창의 새 탭은 세션을 물려받을 수 있다.

**서버를 다시 띄우면 방이 전부 사라진다.** 상태가 전부 메모리에 있기 때문이다.
그 상태에서 게임 화면을 새로고침하면 「방이 사라졌습니다」가 뜨고 목록으로 돌아간다.

## 무엇이 잘못됐는지 어디서 보나

로컬에서는 오류가 `logs/` 에 파일로 쌓인다(2026-08-31). 화면 층에는 테스트 러너가
없어 무엇이 났는지 사람이 보고 옮겨 적어야 했는데, 그 자리를 파일 둘로 바꿨다.

| 파일 | 누가 쓰나 | 언제 처음부터 다시 쓰나 |
|------|-----------|------------------------|
| `logs/server.log` | 소켓 서버 (`server/src/log.ts`) | 서버를 다시 띄울 때 |
| `logs/web.log` | 화면 개발 서버 (`web/vite.config.ts` 의 플러그인) | 개발 서버를 다시 띄울 때 |

**쌓지 않고 덮어쓴다.** 파일이 하나씩 늘면 어느 것이 이번 판의 것인지 고르는 일이
먼저가 된다. 서버를 다시 띄우면 어차피 방이 전부 사라지므로, 그 이전의 줄은 지금
벌어지는 일과 이어지지도 않는다.

브라우저는 파일을 쓸 수 없으므로 화면은 `/__log` 로 보내고 개발 서버가 받아 적는다.
받는 자리를 소켓 서버가 아니라 Vite 에 둔 것은 두 가지 때문이다 — 화면과 같은 출처라
CORS 를 열 일이 없고, **파일의 수명이 화면 개발 서버와 같아진다.**

무엇이 남는가.

- 아무도 받지 않은 오류 · `console.error` · `console.warn` (양쪽 모두)
- **거절당한 요청** — `deny` 로 표시된다. 거절은 예외가 아니라 값이라 어디에도
  남지 않던 것이다. 화면이 사람에게 말을 보이고 끝내므로, `call()` 을 지날 때만 볼 수 있다.
- **연결이 오간 시각** — `sock`. 화면의 여러 자리가 「붙어 있는가」로 잠기는데,
  끊긴 것을 화면만 모르고 있으면 「눌러도 아무 일이 없다」로 보인다. 그 둘을 가르는 값이다.

한 화면이 남기는 줄은 500개까지다. 되풀이되는 오류는 끝이 없어서, 한도가 없으면
파일이 같은 줄로만 채워져 정작 처음에 무엇이 났는지가 앞쪽에 묻힌다.

**운영에는 없다.** 서버는 `NODE_ENV=production`(render.yaml)이면 아무것도 쓰지 않고,
화면 쪽은 `import.meta.env.DEV` 가 false 라 알맹이가 배포본에서 통째로 떨어져 나간다
(빌드 산출물에 `__log` 가 하나도 없는 것으로 확인했다). 받는 자리도 개발 서버에만 있다.

**테스트는 이 길을 밟지 않는다.** 파일 로그는 `index.ts` 에서만 켜지는데 테스트는
`app.ts` 를 직접 쓴다. 그래서 319→327개를 돌려도 `logs/` 는 그대로다.

## 구조

| 폴더 | 역할 | 배포 |
|------|------|------|
| `shared/` | 카드·핸드 평가·쇼다운 판정·프로토콜. 서버와 웹이 함께 쓴다 | — |
| `server/` | Socket.IO 게임 서버. 상태는 전부 메모리 | Render |
| `web/` | React 클라이언트 (Vite) | Vercel |

**DB 는 쓰지 않는다.** 방보다 오래 사는 데이터가 하나도 없어서 뺄 수 있었다.
계정·전적처럼 서버 재시작을 넘겨야 하는 것을 넣으려면 저장소가 따라온다.
(2026-08-25 에 「지금은 그대로 둔다」로 닫혔다. 필요해지면 비밀번호 없이
`localStorage` 기기 토큰이 제일 싸게 붙는다.)

Node 22.18+ 의 네이티브 TS 실행에 기대어 `shared` 와 `server` 는 **빌드 단계가 없다**.
그래서 `enum` 을 쓸 수 없다(strip-only). const 객체 + union 타입으로 쓰고,
tsconfig 의 `erasableSyntaxOnly` 가 실수를 잡는다.

## 규칙이 어디에 있나

- `shared/src/handEval.ts` — 7장 중 최선의 5장. 사전식으로 비교 가능한 `score` 배열을 준다.
  우열뿐 아니라 **완전히 같음**까지 구분해야 해서 족보 이름이 아니라 배열이다.
- `shared/src/showdown.ts` — 「앞사람보다 같거나 강하면 통과」. 등호를 허용하는 것만으로
  룰북의 true tie 가 자연히 풀린다. 「근육」이 걸리면 같은 족보끼리의 우열이 뒤집힌다.
- `server/src/rooms.ts` — 방. 소켓도 시계도 모른다. 시간을 주입받아 재접속 유예를
  타이머 없이 테스트한다.
- `server/src/game.ts` — 한 판의 진행과 **걸린 카드가 무엇을 하는가**.
- `server/src/extras.ts` — **어느 판에 무엇이 걸리는가**(모드별 뽑기). 규칙과 갈라두어야
  각각 따로 검증된다.
- `server/src/socket.ts` — 배선만. 누가 무엇을 듣는지.

## 붙어 있는 것

**카드 20장 전부**(도전자 10 · 해결사 10)와 **모드 5종**이 돈다.
모드는 기본 · 고급 · 프로 · 마스터 시프 + **직접 고르기**(원작에 없는 모드, 방장이 카드를 고른다).

화면은 메인(`/`) · 방 목록(`/rooms`) · 지난 기록(`/history`) · 방(`/rooms/:code`) ·
게임(`/rooms/:code/game`) · 관전(`/rooms/:code/watch`).
대기실을 관전 중이면 주소에 `?watch=1` 이 붙는다.

카드를 온라인으로 옮기며 생긴 장치가 여럿이다.

- **드로어** — 이번 판에 걸린 카드가 화면 옆에 카드 모양(5:7)으로 붙어 있다. 마우스를 올리면
  설명이 커서 옆에 뜨고, 누르면 뒤집혀 설명·결과·쪽지가 나온다. 해결사는 뒷면에서 쓴다.
- **쪽지** — 카드가 나에게만 알려주는 것은 `game:note` 로 그 사람 소켓에만 간다.
  도착하면 한 번 뜨고, 뒤에는 드로어에서 다시 본다.
- **해결사 배치표** — 「직접 고르기」에서 해결사는 고르는 것이 아니라 **판을 지정한다.**
  가로 한 줄이 카드, 세로 한 칸이 판이다. 세로로는 하나만 서지만(한 판에 한 장)
  가로로는 여럿이어도 된다 — 같은 카드를 1판부터 5판까지 내리 세워도 된다. 「썼는가」가
  판마다 새로 시작하기 때문이다. 빈칸도 뜻이 있어서, 다섯째 칸에만 찍으면 앞의 네 판은
  해결사 없이 지나간다. 이렇게 판별로 짤 수 있다는 것이 다른 모드와 갈리는 지점이다.
- **몇 판짜리 게임인가도 방장이 정한다**(2026-08-25). 「직접 고르기」에서 금고와 경보를
  각각 1~5 로 둔다. 다른 모드는 원작 그대로 3 · 3 이고 마스터 시프만 경보가 2다.
  **배치표의 자리 수가 여기서 나온다** — 판수는 「승 + 패 - 1」이라(둘 다 하나씩 모자란 채로
  맞서면 그다음 판에서 결판난다) 금고를 늘리면 배치표도 함께 늘고, 줄이면 없어질 판에 서
  있던 해결사가 사라진다. 표를 다시 보내라고 하는 대신 서버가 길이를 맞춘다(`fitRounds`).
  금고 눈금도 상수가 아니라 서버가 보낸 수만큼 그린다(`GameView.vaultsToWin`).
- **무작위 도전자**(2026-08-26 개정). 「직접 고르기」에서 고른 것 위에 최대 세 장을 더 얹는다.
  **판마다 새로 뽑는다** — 고른 카드(고정)와는 겹치지 않고, 지난 판에 나왔던 카드는 다시
  나올 수 있다. 처음에는 시작할 때 한 번만 뽑았는데, 그러면 「무작위」라기보다 「몰라서 고른
  고정」이었다. 무작위만 얹고 아무것도 고르지 않아도 시작할 수 있다 — 걸릴 카드가 있는
  것이라 「고른 것이 없다」에 들지 않는다.
  - **이긴 다음에만**(기본 꺼짐) — 원작의 「성공하면 어려워진다」를 쓰고 싶을 때 켠다.
  - **누적**(기본 꺼짐) — 한 번 나온 카드가 그대로 남아 판이 갈수록 쌓인다. 이미 걸린
    카드는 다시 뽑지 않으므로 매 판 새 카드가 그만큼 더해진다.
  - 고른 카드는 두 조건과 무관하게 늘 걸린다. 그것이 「고정」의 뜻이다.
  - 빠른 접근 ↔ 감지기는 뽑는 자리에서 지킨다. 이미 걸려 있는 것과 부딪히는 카드는
    애초에 후보에서 뺀다.
- **해결사의 조건과 무작위**(2026-08-26). 배치표에 **맨 윗줄 「무작위」**가 생겼다. 찍어둔
  판에서는 그 자리에서 한 장을 뽑는다. 한 판에 해결사는 하나뿐이라 지정 카드와 같은 칸에
  함께 설 수 없고, 나중에 찍은 쪽이 자리를 가진다. **「진 다음에만」은 기본으로 켜져 있다** —
  원작에서 해결사는 실패한 판을 거들어주는 카드다. 끄면 결과와 무관하게 표대로 나온다.
  - **조건을 켜 두면 첫 판에는 나오지 않는다.** 「직전 판을 졌을 때」인데 직전 판이 없다.
    1판에 찍어두고 조건을 켜 두면 그 칸은 영영 안 나온다는 뜻이라, 화면에 그 사실을 적었다.
- **뒤로가기**(2026-08-26). 휴대폰의 뒤로가기는 브라우저 뒤로가기와 같은 것이라, 그냥 두면
  화면이 통째로 바뀐다. 세 층으로 갈라 받는다 — **덮개가 떠 있으면 덮개만 닫고**(확인창·
  선택창·대화·서랍·연습 안내), **판이 도는 중이면 「나갈까요?」를 묻고**, **대기실이면
  방에서 나간다**(자리를 비우고 관전 목록에서도 빠진다). 방법은 하나뿐이다 — 지킬 것이
  있는 동안 히스토리에 빈 칸을 하나 쌓아 두고(`web/src/lib/back.ts`), 뒤로가기가 그 칸을
  먹을 때 대신 처리한다. 주소는 그대로다.
  - 판에서 그냥 나가게 두면 화면만 목록으로 가고 자리는 남아, **라운드가 내 확정을
    기다리며 선다.** 남들 화면에는 아무 일도 없는데 판만 멈춘다.
  - **보이는 층 하나에 칸 하나다.** 확인창이 뜨는 동안에는 그 아래 층의 가드를 아예
    내려놓고(`active` 를 끈다), 창이 닫히면 다시 세운다. 한 층이 칸을 둘 쌓기 시작하면
    셈이 어긋나 확인창이 되풀이된다 — 실제로 그렇게 났다.
  - 신호를 받는 자리도 하나다. 지키는 것들을 쌓아 두고 **가장 나중에 쌓인 것 하나**에만
    넘긴다. 각자 리스너를 달면 한 번의 뒤로가기를 여럿이 나눠 먹는다.
  - 단추로 닫혔으면 자기 칸을 도로 걷어낸다. 남기면 뒤로가기 한 번이 헛돈다. 자기 칸이
    없으면(뒤로가기가 이미 먹었으면) 손대지 않는다 — 남의 칸을 걷어내게 된다. 라우터가
    화면을 옮기며 정리하는 경우에도 맨 위가 이미 라우터의 칸이라 건드리지 않는다.
- **작은 화면의 시트**(2026-08-26). 640px 아래에서는 뜨는 것들이 아래에서 올라오는 시트가
  된다. 폭은 화면 끝까지, 높이는 `--app-height` 기준이다(키보드가 올라온 만큼 줄어야 대화
  입력칸이 안 가린다). 연습 안내만 위에 남는다 — 아래에 붙이면 「토큰을 누르세요」가
  가리키는 그 토큰을 덮는다.
- **화이트/다크** — 오른쪽 위 단추 하나로 바꾼다. 한 번도 누르지 않았으면 기기 설정을 따르고,

  누른 뒤에는 그 뜻이 이긴다(`localStorage`). 어느 쪽인지는 늘 `<html data-theme>` 에 적혀 있다.
- **다 같이 하는 단계** — 정해진 시점에 전원이 한 번씩 움직인다. 「조율가」·「사기꾼」은 딜 직후,
  스캔(「망막」·「지문」)은 마지막 사람이 공개되기 전. 스캔은 표가 서로 보여서 말 없이도
  만장일치로 옮겨간다. 둘 다 걸리면 둘 다 맞혀야 한다.

- 채팅이 있다(2026-08-25). 원작의 「카드 이야기 금지」는 사람끼리 지키는 약속이지 화면이
  막을 일이 아니라고 보고 넣었다. 대화는 **방에 속한다** — 대기실에서 판으로, 판에서 다시
  대기실로 이어지고, 방이 닫히면 함께 사라진다. 서버가 마지막 50줄을 들고 있다가 들어올 때
  건네고, 창은 `sessionStorage` 에 300줄까지 따로 들고 있다가 번호로 합친다.
  번호는 **방마다** 센다 — 그래야 「번호가 안 이어짐 = 사이가 빠짐」이 성립해서
  「이 사이의 대화는 남아 있지 않습니다」를 정확한 자리에 그릴 수 있다.
- 번호만으로는 같은 방인지 알 수 없다. 방 번호는 네 자리라 닫힌 방의 번호가 다시 쓰이는데,
  그러면 창에 남은 옛 대화가 남의 새 방에 섞인다. `chat:history` 가 **방이 열린 시각**을
  함께 건네고, 창은 번호와 시각이 둘 다 같을 때만 이어 붙인다.
- **내보내기**(2026-08-25). 방장이 **대기실에서만** 쓴다 — 판이 도는 중에 자리가 비면
  라운드가 끝나지 않아 판이 통째로 접히는데, 그건 내보내기가 아니라 판을 엎는 것이다.
  차단은 고를 수 있게 두었다(그냥 내보내기 / 차단하기). 차단은 그 방에만 남고 방이 닫히면
  함께 사라진다.
- **관전**(2026-08-25). 자리 없이 보기만 한다. **공개 상태에 홀카드가 원래 없어서**
  가리는 장치를 새로 만들 필요가 없었다 — 손패(`game:hand`)만 안 가면 된다.
  - 대기실에서도 판에서도 볼 수 있고, 앉아 있던 사람이 스스로 물러날 수도 있다(대기실만).
    혼자 있는 방에서는 물러날 수 없고, 방장이 물러나면 앉은 사람에게 넘어간다 —
    구경꾼은 방장이 될 수 없다.
  - 한 방에 다섯까지(`MAX_SPECTATORS`). 시작 인원에 들지 않고, 지켜줄 자리가 없으므로
    끊기면 그 자리에서 빠진다. 말은 할 수 있되 「관전」 표시가 붙는다.
  - 화면은 주소에 `?watch=1` 로 남긴다. 상태로만 들고 있으면 새로고침 한 번에
    구경꾼이 선수가 된다.
- **공개는 한 명씩**(2026-08-26). 판이 끝나면 서버는 모두의 홀카드를 공개 상태에 싣는다.
  그대로 그리면 덮개 뒤에서 전원의 카드가 한꺼번에 뒤집혀 모달의 연출이 시작부터 무너진다.
  **좌석도 모달과 같은 배열·같은 순서(토큰 오름차순)로 열린다.** 조합 보기는 읽는 차례로
  세운다 — 짝이 앞, 나머지는 높은 것부터, 휠(A2345)만 A 를 맨 뒤로(`orderForReading`).
- **스캔 창 안에 판을 다시 그린다**(2026-08-26). 망막·지문 스캔은 지목된 사람의 손을
  어림해 답하는 것인데 그 창이 테이블을 덮는다. 창 안에 **공용 카드 다섯 장과 전원의 선언
  이력**을 옮겨 두고 지목된 줄만 금색으로 세운다. 이력은 라운드가 끝날 때 기록되고 스캔은
  4라운드가 끝난 뒤 열리므로, 창이 열릴 때 네 라운드가 이미 다 찍혀 있다.
- **판을 넘기는 것은 앉은 사람들이 정한다**(2026-08-26). 「다음 금고로」와 「재경기 제안」은
  구경꾼에게 잠긴다 — 세는 것만 보인다. 서버가 어차피 「이 판에 참여하고 있지 않습니다」로
  돌려보내므로, 열어두면 눌러도 아무 일이 없어 고장으로 읽힌다.
- **경기 기록**(2026-08-25). `localStorage` 에 **닉네임을 키로** 승·패·중도포기.
  창이 달라도 이름이 같으면 쌓인다(정체성 `playerId` 는 창마다 달라 그것으로 세면
  창을 새로 열 때마다 0 부터다). **끝을 본 판만** 센다 — 그 셋이 끝점이라 새로고침으로
  두 번 세지 않는다. 연습·관전은 세지 않는다. 방 목록 → `/history`.
- **화면 축소**(2026-08-25). 작은 휴대폰을 위한 단추다 — 늘 켜져 있는 것이 아니라
  오른쪽 위 도구 줄의 화살표(「화면 작게」)를 눌러야 걸린다. 켜면 뿌리에서 `zoom: 0.85` 한 벌이라
  여백·글자·카드·토큰이 같은 비율로 함께 작아진다. 값을 하나씩 줄여 잡으면 규칙이 수십 개로
  늘고 어디 하나는 반드시 어긋난다. 고른 뜻은 `localStorage` 에 남고, 테마와 같은 이유로
  `index.html` 이 화면이 그려지기 전에 `<html data-density>` 에 적는다 — 뒤늦게 붙이면
  한 칠은 큰 채로 나온다.
- **혼자 해보기**(2026-08-25). 봇 둘이 앉은 보통 판이다 — 규칙도 화면도 새로 쓴 것이 없고,
  `server/src/tutorial.ts` 가 「봇이 언제 무엇을 누르는가」와 「어디서 멈춰 무엇을 알려주는가」만
  들고 있다. 도전자·해결사 없는 기본 모드, 금고 하나로 끝.
  - 봇은 서로의 패를 안다. 그래서 봇끼리는 순서를 틀리지 않고 서로의 토큰도 뺏지 않는다.
    번호는 「남은 카드에서 상대 손을 120번 뽑아 몇 번 이기는지」로 어림한 백분위에서 고른다.
    한 수마다 1초를 둔다(`BOT_DELAY_MS`) — 3초는 라운드마다 12초씩 멍하니 기다리게 했다.
  - 안내가 떠 있는 동안 봇이 멈춘다(`tutorial:next` 를 받아야 다시 흐른다). 읽는 사이에 판이
    흘러가면 무엇을 읽었는지와 화면이 어긋난다.
  - 튜토리얼 방은 목록에 뜨지 않고, 사람이 빠지면 그대로 닫힌다 — 봇만 남은 방은 인원이
    0 이 아니라 저절로 닫히지 않는다.
- **쥔 토큰을 내려놓을 수 있다**(2026-08-26). 쥐고 있던 것을 다시 누르면 중앙으로 돌아간다.
  선언을 무르는 자리가 있어야 하기 때문이다 — 남의 것을 뺏어야만 내 것을 놓을 수 있으면,
  생각이 바뀐 사람은 남의 자리를 흔들지 않고서는 물러설 수 없다. 붙박이(「소음 감지기」·
  「환기구」)만 그대로다. 한 사람이 무르면 **모두의 확정이 풀린다** — 한 자리가 비면
  남의 판단도 달라지기 때문이다. 되돌아가는 동안에도 그 토큰은 잠겨 있다.
- **소리**(2026-08-26). 효과음은 파일이 아니라 그 자리에서 만드는 파형이다(`sfx.ts`).
  칩 딸깍·딩·사이렌은 노이즈와 사인파에 엔벨로프를 씌운 것이라, 녹음을 구해 오는 것보다
  숫자 몇 개를 만지는 편이 빠르다 — 번들이 늘지 않고, 공개된 화면이라 늘 따라오던 출처
  문제도 없다. 스물여섯 갈래가 돈다.
  - **토큰은 내 것과 남의 것이 갈린다.** 한 번의 뺏기가 두 사람의 자리를 함께 바꾸므로
    「새로 쥔 쪽」에서만 울리고, 빈자리는 그 토큰이 중앙으로 돌아갔을 때에만, 곧 스스로
    내려놓았을 때에만 운다. 그러지 않으면 한 동작에 두 번 난다. 내 것을 뺏긴 경우에는
    뺏겼다는 소리가 이미 울리므로 남의 집는 소리를 건너뛴다. 남의 소리는 내 것보다 한참
    작다 — 열 명이 앉은 판에서 같은 크기로 울리면 정작 내 손이 묻힌다.
  - **쇼다운은 한 사람마다 반음씩 오른다.** 사슬이 이어지는 중임을 글자보다 먼저 알린다.
    금고·경보와 승리·패배를 따로 둔 것은 층위가 달라서다 — 저쪽은 판 하나의 결말이고
    이쪽은 여기서 자리를 뜬다는 뜻이라, 1.5초를 두고 뒤에 온다.
  - **단추는 클래스와 `aria-pressed` 로 갈린다.** 확정·나가기·취소·토글이 저마다 다르되
    컴포넌트는 한 줄도 고치지 않았다. 문서에서 한 번만 듣고 눌린 것이 무엇인지 보므로,
    새로 만드는 단추도 클래스만 맞으면 따라온다. 토큰과 잠긴 단추는 뺀다 — 앞의 것은
    자기 소리가 따로 있고, 뒤의 것은 눌러도 아무 일이 없는데 소리가 나면 눌린 줄 안다.
  - **배경음악은 받아 온 파일**이고 셋 다 CC0 다(만든 사람은 README 에 적어 두었다).
    화면에 부르는 이름을 곡 제목이 아니라 분위기(잠입·추리·재즈)로 둔 것은, 고르는 사람이
    곡을 아는 것이 아니라 분위기를 고르기 때문이다. 곡을 바꿀 때만 처음부터 시작하고
    크기를 만질 때는 흐르던 자리를 지킨다 — 매번 되감기면 듣던 데를 잃는다.
  - **크기는 `audio.ts` 한 곳에 모았다.** 효과음과 배경음악은 나는 방식이 전혀 다르지만
    사람이 만지는 손잡이는 하나여야 한다. 음소거를 크기 0 과 따로 둔 것은 되돌아올 자리
    때문이다 — 슬라이더를 내려 끄면 다시 켤 때 얼마였는지 잊는다.
  - 브라우저는 사람이 한 번 누르기 전까지 소리를 내주지 않는다. 그래서 배경음악의 첫
    재생은 거의 언제나 거절당하고, 그것을 실패로 보지 않고 첫 손짓을 기다렸다가 다시 건다.

## 겪어서 알게 된 것 (다시 밟지 말 것)

**CSS 미디어 쿼리는 파일 끝에 모은다.** 기본 규칙보다 앞에 두면 우선순위가 같아
나중에 오는 기본 규칙이 이긴다. 오류 없이 조용히 안 먹어서 두 번 헤맸다
(모바일 캐러셀, 로고 크기). `styles.css` · `game.css` 둘 다 끝에 모아 두었다.

**등장 애니메이션의 fill 은 `backwards` 다.** `both` 로 두면 끝난 뒤에도 `transform` 을
붙들어, 강조 같은 다른 변형이 먹지 않는다. 그것 때문에 강조를 애니메이션으로 만들었다가
강조가 꺼질 때 카드가 다시 날아드는 버그가 났다.

**소켓 테스트는 「다음 이벤트 하나」로 기다리면 안 된다.** 직전 동작이 만든 브로드캐스트를
잘못 집는다. 조건으로 기다리거나(`until`), 각자가 받은 상태를 모아 두고 되짚는다(`waitState`).
같은 실수를 두 번 했다.

**폭을 정하지 않은 부모 안에서 `width: 100%` 는 아주 좁게 잡힌다.** 드로어가 그랬다.

**한 파일을 짧은 사이에 두 번 쓰면 Vite 가 중간 상태를 캐시한다.** 「쓰는 곳은 있는데
정의가 없는」 코드가 브라우저로 가서 `X is not defined` 가 났다. 디스크의 파일은 멀쩡하고
`npm run build --workspace @the-gang/web` 도 통과해서 한참 헤맸다. 편집이 여러 번 나뉘었으면 마지막에 `touch` 한다.

**인자 없는 `socket.off('연결')` 은 그 이벤트를 듣던 모두를 떼어낸다.** 게임 화면을
벗어날 때 그것을 불러, 연결 표시등이 등록해 둔 것까지 함께 날아갔다. 그 뒤로는 소켓이
멀쩡히 재접속해도 화면이 「끊김」인 채로 남는다. 증상이 「재접속이 안 된다」로 보여서
소켓을 한참 의심했는데, 실제로는 이미 붙어 있었다. 뗄 때는 핸들러를 지정한다.

**서버 상태 객체를 useEffect 의존성에 넣지 않는다.** 상태는 누가 토큰만 집어도 새로 오므로
매번 정리 함수가 돌아 타이머가 취소된다. 키 문자열 하나에만 맨다.

**은닉 정보는 통로를 하나로 묶는다.** 공개 상태(`GameView`)에는 쇼다운 전까지 누구의
홀카드도 없다 — 본인 것조차 없다. 스캔 중 지목된 사람의 카드도 답이 정해질 때까지
서버 밖으로 나가지 않는다. 미리 보내고 화면에서만 가리면 통신을 열어보는 것으로 답을 안다.

**색은 두 벌이지만 물건은 한 벌이다.** 밝은 쪽을 만들 때 카드·토큰·초록 펠트까지 뒤집으면
안 된다 — 조명이 바뀐다고 트럼프가 검게 변하지는 않는다. 그래서 `--felt` 는 두 테마가 같은 값을
쓰고, 로비 목록의 바탕은 `--surface` 로 갈라두었다. 처음에 둘을 한 토큰으로 두었다가
밝은 쪽에서 초록 위에 검은 글씨가 났다.

**테마는 화면이 그려지기 전에 정해야 한다.** React 가 뜬 뒤에 `data-theme` 을 붙이면
첫 한 칠이 어두운 채로 나왔다가 밝아진다. `index.html` 의 인라인 스크립트가 먼저 정한다.

**손패가 바뀌는 경로를 빠뜨리기 쉽다.** 감지기가 카드를 갈아엎어도 새 손패를 보내지 않아
화면에 옛 카드가 남았다. 지금은 라운드가 넘어갈 때 손패를 함께 보낸다.

**우리가 부른 `history.back()` 도 popstate 로 돌아온다.** 그것을 사람이 누른 것으로 받으면
엉뚱한 일이 벌어진다. 개발 모드는 효과를 두 번 실행하므로 「쌓기 → 걷어내기 → 다시 쌓기」가
일어나는데, 걷어내며 부른 back 이 새 가드에 잡혀 **방을 만들자마자 나가졌다.** 스스로 부른
back 은 세어 두었다가 그 신호를 흘려보낸다(`web/src/lib/back.ts` 의 `unwinding`).
세는 자리는 훅이 아니라 파일이다 — 걷어내는 쪽과 받는 쪽이 서로 다른 가드일 수 있다.

**모듈을 갈아엎으면 문서에 붙은 리스너가 옛 것을 붙든다.** 소리의 저장 로직을 `sfx.ts` 에서
`audio.ts` 로 들어냈는데, 단추 소리를 듣는 리스너는 `document` 에 붙어 있어서 옛 모듈의
함수를 그대로 들고 있었다 — 음소거를 눌러도 단추 소리가 났다. 코드는 멀쩡하고 새로고침하면
사라진다. 인자 없는 `socket.off` 나 Vite 의 중간 상태 캐시와 같은 계열이다.

## 남은 일

**1. 돌려보며 드러나는 것 줍기**

친구들에게 뿌렸고, 버그·개선사항은 구글 시트(또는 폼)로 받는다. 칸은 넷이다 —
이름 · 내용 · 분류(버그/불편/제안) · 화면(로비/방/게임/결과).

**무료 요금제는 15분 무트래픽이면 잠들고, 깨어날 때 방이 전부 사라진다.** 첫 접속자가
1~2분 기다리는 자리는 `ServerGate` 가 덮는다. 사람들을 부르기 전에 `/healthz` 를 한 번
열어 깨워두면 그 기다림이 없다. 리전은 싱가포르다.

**아직 push 하지 않은 커밋이 하나 있다** — `c8e0cde`(CSS 순서 정리). 화면에 달라지는 것이
없어 급하지 않고, 다음에 무언가 고칠 때 함께 나가면 된다.

**2. 눈으로 확인되지 않은 것**

에이전트 쪽에서는 브라우저를 띄우지 못한다(확장이 붙지 않는다). 레이아웃·애니메이션은
사용자가 직접 보고 알려주는 방식으로 진행해 왔고, 그렇게 잡은 것이 여럿이다.

2026-08-26 배포 직후 **뒤로가기 네 경로는 사용자가 확인했다**(방 만들기 · 판에서 뒤로가기 →
확인창 → 계속하기 · 방 나가기 · 판을 나온 뒤 뒤로가기). 아직 안 본 자리는 이렇다.

- **모바일 시트** — 모달·대화·소리 패널·스캔이 폭과 높이를 제대로 쓰는지, 키보드가 올라올 때
  대화 입력칸이 가리지 않는지, 대화 머리를 아래로 밀면 닫히는지.
- **스캔 창 안의 판** — 공용 카드와 선언 이력이 답할 만하게 놓였는지. 스캔 둘이 함께 뜰 때도.
- **직접 고르기의 새 설정** — 무작위 장수·조건 둘·배치표 맨 윗줄이 손에 붙는지.
- **밝은 쪽 게임 화면** — 펠트 위의 카드·토큰·결과 글자.
- **테이블 양옆 카드**(1024px 이상)와 도전자 넘기기 화살표.
- **소리가 겹칠 때** — 열 명이 앉은 판에서 남의 칩이 겹쳐 울릴 때, 쇼다운의 계단이 1.9초
  간격으로 흐를 때, 대화가 오가는 사이에 판 소리가 묻히지 않는지. 숫자는 `sfx.ts` 의 `case`
  안에 모여 있고 전체 크기는 `audio.ts` 의 `SFX_MAX` 하나다. 개발 중에는 콘솔에서
  `__sfx('vault')` 처럼 하나씩 불러 볼 수 있다(배포본에는 없다).

**`web/` 에는 테스트 러너가 없다.** 화면 층은 타입 검사와 빌드까지만 보증된다. 서버·규칙은
319개 테스트가 지킨다. 붙인다면 vitest + Testing Library 이고, 기록·축소·모달 겹침 정도는
자동으로 잡을 수 있다 — 새 설비라 별도 작업으로 잡아야 한다.

**3. 알면서 그대로 둔 것**

- 대기실에서 **Esc 는 「나갈까요?」를 묻고 뒤로가기는 바로 나간다.** 뒤로가기는 폰 동작이라
  그렇게 정했다. 맞추려면 한 줄이다.
- **구경꾼이 브라우저 뒤로가기로 목록에 가면 방에 남는다.** 판이 접혀 나가는 길만 고쳤다
  (그때는 `room:leave` 를 부른다). 자리에 앉은 사람이 뒤로가기 하는 것과 같은 처리라 두었다.
- **「방장이 판을 접었습니다」 안내가 거의 안 보인다.** 방 상태 갱신(`room:updated`)이 먼저
  도착해 즉시 대기실로 옮긴다. 살리려면 그 이동을 안내가 끝날 때까지 미뤄야 한다.
- **재경기 제안**은 화면에서 구경꾼에게 잠갔지만 서버가 어떻게 답하는지는 확인하지 않았다.
- `bc08e44` 커밋에 **효과음 파일이 섞여 있다.** 다른 세션의 작업이 트리에 있는 채로
  `git add -A` 를 했다. 되돌리지 않기로 했다 — 빌드는 멀쩡했고 푸시 전이었다.

**4. 다듬을 거리 (급하지 않음)**

- 해결사를 「먼저 누른 사람이 쓴다」로 두었다. 원작은 다 같이 정하는 것이라,
  제안·동의 절차를 넣을 여지가 있다.
- 「직접 고르기」에서 한 판에 해결사 두 장이 함께 걸리게 하려면 사용 상태·딜 직후 단계·
  드로어를 여러 장 기준으로 다시 짜야 한다.
- 관전자는 채팅을 할 수 있다. 「관전」 표시를 붙여 두었지만, 아예 읽기 전용으로 두는 쪽이
  규칙에는 더 맞을 수 있다. 실제로 써 보고 정한다.
- 튜토리얼은 금고 하나로 끝난다. 마지막에 「정식 게임은 금고 3개」를 알리는 안내를 넣지
  않았다 — 결과 화면이 이미 꽉 차서 겹친다. 넣으려면 결과 패널 안의 한 줄이어야 한다.
- 곡 고르기 단추는 라디오인데 소리는 `aria-pressed` 로 가른다. 그래서 이미 고른 곡을 다시
  누르면 「꺼짐」 소리가 난다. 이미 켜진 것을 다시 누르는 일이 드물어 그대로 두었다.

## 대화하며 정해진 작업 방식

- 화면·디자인 결정은 옵션을 내고 사용자 확인을 받는다.
- 서버 코드가 바뀌면 재시작이 필요하고 **그때 방이 전부 사라진다.** 사용자가 게임 중일 수
  있으니 재시작 전에 알리거나 판이 끝나기를 기다린다.
- 커밋 메시지에 모델 attribution 을 넣지 않는다.
- **같은 저장소를 두 사람(세션)이 함께 쓴 적이 있다.** `git add -A` 는 남의 작업 중인 파일까지
  쓸어담는다 — 실제로 효과음 작업이 남의 커밋에 섞여 들어갔다. 내가 고친 파일만 지정해서
  add 하고, push 전에는 `git log origin/master..HEAD` 로 남의 커밋이 얹혔는지 본다.
- **화면 층은 눈으로만 확인된다.** 고친 뒤 「무엇을 어디서 눌러 보면 되는지」를 함께 적어
  사용자에게 넘긴다. 서버·규칙은 테스트가 지키므로 그쪽은 바로 확인할 수 있다.
- **한 건 고치면 그 자리에서 빌드하고 테스트한 뒤 다음으로 넘어간다.** 여러 건을 겹쳐
  고치면 깨진 것이 어느 변경 때문인지 가려내는 데 더 든다.
- 한 파일을 짧은 사이에 두 번 쓰면 Vite 가 중간 상태를 캐시한다. 편집이 나뉘었으면
  마지막에 `touch` 한다.
- 원인을 추측하지 말고 재현부터 한다. 새로고침 버그는 서버에 직접 쳐 보고 서버가
  정상임을 확인한 뒤 화면으로 좁혔다.
