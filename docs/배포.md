# 배포 — Render(소켓) + Vercel(화면)

한 덩어리로 보이지만 두 곳에 나뉘어 산다. 화면은 정적 파일이라 어디서 주든 같고,
소켓 서버는 사람이 붙어 있는 동안 깨어 있어야 한다. 필요한 것이 달라서 갈랐다.

둘은 서로의 주소를 알아야 한다. 그래서 **한쪽을 먼저 띄우고, 다른 쪽을 띄운 뒤,
처음 쪽으로 돌아와 주소를 채우는** 순서가 된다. 아래 차례가 그 이유로 이 모양이다.

| 무엇 | 어디 | 무엇으로 정하나 |
|------|------|----------------|
| 소켓 서버 (`server/`) | Render | `render.yaml` |
| 화면 (`web/`) | Vercel | `vercel.json` |
| 공용 규칙 (`shared/`) | — | 둘 다 저장소째 받아 쓴다 |

---

## 1. GitHub 저장소 만들기

Render 와 Vercel 둘 다 저장소를 보고 배포한다. 지금 이 저장소에는 remote 가 없다.

**할 일**

1. GitHub 에서 빈 저장소를 만든다 (README·.gitignore 없이 비워 둘 것 — 이미 있다)
2. 아래를 실행한다

```bash
cd 개인프로젝트/the-gang
git remote add origin https://github.com/<계정>/<저장소>.git
git push -u origin master
```

**주의** — 브랜치가 `main` 이 아니라 `master` 다. GitHub 기본값과 다르니
Render·Vercel 에서 배포 브랜치를 고를 때 `master` 를 골라야 한다.

---

## 2. Render — 소켓 서버

**할 일**

1. Render 에서 **New → Blueprint** 를 고르고 저장소를 잇는다 (`render.yaml` 을 읽는다)
2. 브랜치를 `master` 로 둔다
3. 뜨는 대로 승인하고 배포를 기다린다
4. 주소를 받아 적는다 — `https://the-gang-server-XXXX.onrender.com` 꼴

**이때 `CORS_ORIGINS` 는 비워 둔다.** 아직 화면 주소를 모른다. 비어 있으면
`http://localhost:5173` 만 허용하므로, 지금 단계에서 배포된 화면은 아직 못 붙는다. 정상이다.

**확인**

```
https://<받은 주소>/healthz   →   {"ok":true,"rooms":0}
```

Blueprint 대신 손으로 만들 거면 값은 이렇다.

| 항목 | 값 |
|------|-----|
| Runtime | Node |
| Region | **Singapore** |
| Build Command | `npm install` |
| Start Command | `npm start --workspace @the-gang/server` |
| Health Check Path | `/healthz` |
| `NODE_VERSION` | `22.18.0` |
| `MAX_CONNECTIONS` / `MAX_ROOMS` | `40` / `8` |

---

## 3. Vercel — 화면

**할 일**

1. Vercel 에서 저장소를 잇는다. **Root Directory 는 저장소 뿌리 그대로 둔다**
   (`web/` 로 바꾸지 말 것 — `shared/` 가 밖에 있어 빌드가 깨진다)
2. **빌드 전에** 환경변수를 넣는다

   | 이름 | 값 |
   |------|-----|
   | `VITE_SOCKET_URL` | 2단계에서 받은 Render 주소 |

3. 배포하고 주소를 받아 적는다 — `https://<이름>.vercel.app`

**주의** — `VITE_SOCKET_URL` 은 **빌드할 때 파일 안에 박힌다.** 배포한 뒤에 값을
넣으면 이미 만들어진 화면은 여전히 `localhost:3001` 을 본다. 나중에 바꿨다면
반드시 다시 배포해야 한다. 화면은 멀쩡한데 영영 연결이 안 되는 모양으로 나타난다.

---

## 4. Render 로 돌아가 화면 주소 채우기

**할 일**

1. Render 의 서비스 → Environment → `CORS_ORIGINS` 에 3단계 주소를 넣는다

```
https://<이름>.vercel.app,*.vercel.app
```

2. 저장하면 알아서 다시 뜬다

뒤의 `*.vercel.app` 는 배포마다 주소가 바뀌는 **프리뷰**까지 열어준다. 본 주소만
쓸 거면 앞의 하나로 충분하다.

---

## 5. 확인

1. Vercel 주소를 연다
2. 이름을 넣고 방을 만든다 — **방이 만들어지면 소켓이 붙은 것이다**
3. 다른 창(시크릿 창)으로 같은 방에 들어가 3명을 채우고 한 판 돌린다

붙지 않으면 브라우저 콘솔의 오류가 어느 쪽인지 갈라준다.

- `CORS` / `origin` → 4단계의 `CORS_ORIGINS` 가 안 맞는다
- `localhost:3001` 로 붙으려 한다 → 3단계의 `VITE_SOCKET_URL` 이 빌드에 안 들어갔다

---

## 띄우고 나면 달라지는 것

**무료 요금제는 15분 동안 아무도 안 오면 잠든다.** 깨어나는 데 1분 가까이 걸리고,
**깨어날 때 방이 전부 사라진다.** 상태가 전부 메모리에 있기 때문이다(DB 가 없다).
첫 사람이 들어올 때 화면이 한참 「연결이 끊겼습니다」를 보이다가 붙는 것은 이 때문이다.
미리 `/healthz` 를 한 번 열어 깨워두면 사람이 기다리지 않는다.

**리전은 싱가포르여야 한다.** 다른 리전은 한국에서 왕복 150ms 를 넘겨, 토큰을
집을 때마다 굼뜬 느낌이 든다.

---

## 다시 밟지 말 것

**Vercel 의 Root Directory 를 `web/` 로 바꾸지 않는다.** 화면은 `@the-gang/shared` 의
**소스 .ts** 를 직접 가져다 쓴다. 뿌리에서 설치해야 작업공간이 이어진다.

**Render 에서 서버는 빌드 단계가 없다.** `.ts` 를 그대로 실행한다(Node 22.18+).
`node_modules/@the-gang/shared` 는 심볼릭 링크라 Node 가 실제 경로(`shared/src/…`)로
풀어 읽는다 — node_modules 안의 파일이었다면 타입 제거가 거부됐을 것이다.
`npm install` 이 링크를 만들어 주므로 설치를 건너뛰거나 파일을 복사해 넣으면 깨진다.

**`VITE_SOCKET_URL` 은 빌드 시점 값이다.** 런타임에 읽지 않는다.
