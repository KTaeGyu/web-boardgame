# 배포 — Render(소켓) + Vercel(화면)

한 덩어리로 보이지만 두 곳에 나뉘어 산다. 화면은 정적 파일이라 어디서 주든 같고,
소켓 서버는 사람이 붙어 있는 동안 깨어 있어야 한다. 필요한 것이 달라서 갈랐다.

둘은 서로의 주소를 알아야 한다. 그래서 **한쪽을 먼저 띄우고, 다른 쪽을 띄운 뒤,
처음 쪽으로 돌아와 주소를 채우는** 순서가 된다. 아래 차례가 그 이유로 이 모양이다.

| 무엇 | 어디 | 무엇으로 정하나 |
|------|------|----------------|
| 소켓 서버 (`server/`) | Render | `render.yaml` |
| 화면 (`web/`) | Vercel | `vercel.json` |
| 공용 규칙 (`shared/`) | — | 둘 다 저장소째 받아 쓴다 |

---

## 지금 어디에 있나 (2026-08-25 배포 완료)

| 무엇 | 주소 |
|------|------|
| 화면 | https://web-boardgame.vercel.app |
| 소켓 서버 | https://web-boardgame-server.onrender.com |
| 저장소 | https://github.com/KTaeGyu/web-boardgame (브랜치 `master`) |

**push 하면 둘 다 나간다.** Vercel 은 화면을 새로 빌드하고, Render 는 서버를 새로
빌드해 재시작한다. **서버가 재시작되면 떠 있던 방이 전부 사라진다** — 상태가 전부
메모리에 있기 때문이다. 사람이 하고 있을 수 있으니 `/healthz` 의 `rooms` 를 먼저 본다.

아래는 처음 세울 때의 절차다. 다시 세울 일이 있으면 이 순서로 간다.

---

## 1. GitHub 저장소 만들기

Render 와 Vercel 둘 다 저장소를 보고 배포한다.

**할 일**

1. GitHub 에서 빈 저장소를 만든다 (README·.gitignore 없이 비워 둘 것 — 이미 있다)
2. 아래를 실행한다

```bash
cd 개인프로젝트/the-gang
git remote add origin https://github.com/<계정>/<저장소>.git
git push -u origin master
```

**주의** — 브랜치가 `main` 이 아니라 `master` 다. GitHub 기본값과 다르니
Render·Vercel 에서 배포 브랜치를 고를 때 `master` 를 골라야 한다.

---

## 2. Render — 소켓 서버

**할 일**

1. Render 에서 **New → Blueprint** 를 고르고 저장소를 잇는다 (`render.yaml` 을 읽는다)
2. 브랜치를 `master` 로 둔다
3. 뜨는 대로 승인하고 배포를 기다린다
4. 주소를 받아 적는다 — `https://the-gang-server-XXXX.onrender.com` 꼴

**이때 `CORS_ORIGINS` 는 비워 둔다.** 아직 화면 주소를 모른다. 비어 있으면
`http://localhost:5173` 만 허용하므로, 지금 단계에서 배포된 화면은 아직 못 붙는다. 정상이다.

**확인**

```
https://<받은 주소>/healthz   →   {"ok":true,"rooms":0}
```

Blueprint 대신 손으로 만들 거면 값은 이렇다.

| 항목 | 값 |
|------|-----|
| Runtime | Node |
| Region | **Singapore** |
| Build Command | `npm install` |
| Start Command | `npm start --workspace @the-gang/server` |
| Health Check Path | `/healthz` |
| `NODE_VERSION` | `22.18.0` |
| `MAX_CONNECTIONS` / `MAX_ROOMS` | `100` / `20` |
| `NODE_ENV` | `production` — 이게 있으면 파일 로그를 남기지 않는다 |

### 계정을 살리려면 — Contentful 값 셋 (2026-08-31)

**안 넣어도 서버는 뜬다.** 다만 계정이 메모리에만 남아 서버가 잠들 때 함께 사라진다.
넣으려면 Render 의 Environment 에 셋을 더한다.

| Key | 어디서 |
|-----|--------|
| `CONTENTFUL_SPACE_ID` | 스페이스 → Settings → General settings |
| `CONTENTFUL_MANAGEMENT_TOKEN` | 아래 참고 — **개인 액세스 토큰은 안 된다** |
| `CONTENTFUL_ENVIRONMENT` | `master` |

🔴 **계정 설정에서 만드는 개인 액세스 토큰(`CFPAT-…`)은 못 쓴다.** 조직이 막고 있고,
그것을 푸는 자리가 지금 요금제(Access tools 에 SCIM·SSO 뿐)에는 없다. 증상은 이렇다 —
토큰은 살아 있어서 `/users/me` 와 `/organizations` 는 답하는데 `/spaces` 만 빈 목록이고,
스페이스를 직접 부르면 `OrganizationAccessGrantRequired` 가 온다. 계정이 갈렸나 스페이스
ID 가 틀렸나를 한참 뒤졌지만 둘 다 아니었다.

**되는 것은 CLI 의 OAuth 토큰뿐이다.** 일반 터미널 창에서(`!` 로는 입력을 못 받아 죽는다):

```
npx --yes contentful-cli login
```

브라우저 승인 → 나온 값을 그대로 쓴다. 43자쯤이고 `CFPAT-` 로 시작하지 않는다.

**콘텐츠 타입은 `account`**, 필드는 `email`(Short text, Unique) · `passwordHash` ·
`passwordSalt` · `nickname`(Short text) · `wins` · `losses`(**Integer**). 만든 뒤
**활성화(activate)** 해야 항목을 만들 수 있다 — 빠뜨리면 「가입이 안 된다」로만 보인다.

**로컬에서도 쓰려면** 저장소 뿌리에 `.env` 를 만들고 같은 셋을 넣는다. `.gitignore` 가
이미 막고 있고, dev 스크립트가 `--env-file-if-exists=../.env` 로 읽는다.

## 3. Vercel — 화면

**할 일**

1. Vercel 에서 저장소를 잇는다. **Root Directory 를 `./` 로 되돌린다.**
   가져오기 화면이 스스로 `web` 을 골라 놓는데, 그대로 두면 `shared/` 가 밖에 있어
   빌드가 깨지고 Output 도 `web/web/dist` 를 찾는다. 바꾼 뒤에는 Build·Output·Install
   세 칸이 `vercel.json` 값 그대로인지 한 번 더 본다 — 다시 감지하면서 리셋될 수 있다.
2. **빌드 전에** 환경변수를 넣는다

   | 이름 | 값 |
   |------|-----|
   | `VITE_SOCKET_URL` | 2단계에서 받은 Render 주소 |

3. 배포하고 주소를 받아 적는다 — `https://<이름>.vercel.app`

**주의** — `VITE_SOCKET_URL` 은 **빌드할 때 파일 안에 박힌다.** 배포한 뒤에 값을
넣으면 이미 만들어진 화면은 여전히 `localhost:3001` 을 본다. 나중에 바꿨다면
반드시 다시 배포해야 한다. 화면은 멀쩡한데 영영 연결이 안 되는 모양으로 나타난다.

---

## 4. Render 로 돌아가 화면 주소 채우기

**할 일**

1. Render 의 서비스 → Environment 에서 **`CORS_ORIGINS` 를 새로 만든다**

`render.yaml` 이 이 키만 `sync: false` 로 두었다 — 값을 저장소에 적지 않고 대시보드에서
채우라는 뜻이라, Blueprint 를 만들 때 비워 두었으면 **키 자체가 없다.** 고르는 것이
아니라 만드는 것이다. `NODE_VERSION`·`MAX_CONNECTIONS`·`MAX_ROOMS` 셋이 보이면 자리가 맞다.

```
https://<이름>.vercel.app,*.vercel.app
```

2. 저장하면 알아서 다시 뜬다

뒤의 `*.vercel.app` 는 배포마다 주소가 바뀌는 **프리뷰**까지 열어준다. 본 주소만
쓸 거면 앞의 하나로 충분하다.

---

## 5. 확인

1. Vercel 주소를 연다
2. 이름을 넣고 방을 만든다 — **방이 만들어지면 소켓이 붙은 것이다**
3. 다른 창(시크릿 창)으로 같은 방에 들어가 3명을 채우고 한 판 돌린다

붙지 않으면 브라우저 콘솔의 오류가 어느 쪽인지 갈라준다.

- `CORS` / `origin` → 4단계의 `CORS_ORIGINS` 가 안 맞는다
- `localhost:3001` 로 붙으려 한다 → 3단계의 `VITE_SOCKET_URL` 이 빌드에 안 들어갔다

---

## 띄우고 나면 달라지는 것

**무료 요금제는 15분 동안 아무도 안 오면 잠든다.** 깨어나는 데 1분 가까이 걸리고,
**깨어날 때 방이 전부 사라진다.** 상태가 전부 메모리에 있기 때문이다(DB 가 없다).
첫 사람이 들어올 때 화면이 한참 「연결이 끊겼습니다」를 보이다가 붙는 것은 이 때문이다.
미리 `/healthz` 를 한 번 열어 깨워두면 사람이 기다리지 않는다.

**리전은 싱가포르여야 한다.** 다른 리전은 한국에서 왕복 150ms 를 넘겨, 토큰을
집을 때마다 굼뜬 느낌이 든다.

## 다시 밟지 말 것

**Vercel 의 Root Directory 를 `web/` 로 바꾸지 않는다.** 화면은 `@the-gang/shared` 의
**소스 .ts** 를 직접 가져다 쓴다. 뿌리에서 설치해야 작업공간이 이어진다.

**Render 에서 서버는 빌드 단계가 없다.** `.ts` 를 그대로 실행한다(Node 22.18+).
`node_modules/@the-gang/shared` 는 심볼릭 링크라 Node 가 실제 경로(`shared/src/…`)로
풀어 읽는다 — node_modules 안의 파일이었다면 타입 제거가 거부됐을 것이다.
`npm install` 이 링크를 만들어 주므로 설치를 건너뛰거나 파일을 복사해 넣으면 깨진다.

**`VITE_SOCKET_URL` 은 빌드 시점 값이다.** 런타임에 읽지 않는다.

**`render.yaml` 의 `name` 을 바꾸면 서비스가 하나 더 생긴다.** Render 는 이름을 서비스의
정체로 본다. 개명해 주는 것이 아니라 새로 만들고, 옛 이름짜리는 블루프린트에서 떨어져 나온
채 남아 계속 떠 있다. 이름은 처음에 정하고, 이미 갈라졌으면 옛 것을 지운다 — 남겨두면
코드를 고쳐도 갱신되지 않는 유령이 하나 더 도는 셈이다.

**무료 요금제는 잠든다 — 그래서 첫 접속을 덮는다.** 15분 무트래픽이면 내려가고 깨어나는 데
1~2분이 걸린다. 그동안 화면은 `ServerGate` 가 덮고 얼마나 기다렸는지 센다. 5분을 넘기면
잠든 것이 아니라 무언가 잘못된 것이므로 문구가 바뀐다.
