# LLM 플레이어 — 계획

**아직 만들지 않았다.** 이 문서는 종이 위 설계이고, 손대는 시점은 아래 「언제」에 있다.

---

## 왜 만드나 — 게임을 위해서가 아니다

정직하게 적어 둔다. **이직 준비의 산출물이다.**

목표 직무가 **백엔드**인데 회사 프로젝트는 소스를 못 보여준다. 이 저장소는 **유일하게
코드와 돌아가는 화면을 함께 보여줄 수 있는 것**이고, 그래서 「LLM 을 실제 서비스에
붙이며 겪은 것」을 여기에 만든다.

⚠️ **「AI 를 만들었다」가 아니라 「AI 를 붙이며 겪은 것」이 파는 물건이다.** 모델을
다루는 흉내를 내면 진짜 AI 엔지니어들과 비교당한다. **지연 · 비용 · 실패 · 프롬프트
버전**을 다룬 이야기가 백엔드 지원자에게 맞는 크기다.

⚠️ **봇이 세다고 좋은 것이 아니다.** 사람이 사람과 하는 게임이고, 봇은 **인원이 모자랄 때
자리를 메우는 것**이다. 게임을 봇 중심으로 다시 짜지 않는다.

## 언제 — 2027.01 이후

**코딩테스트가 먼저다.** 2026.10~2027.01 은 거기에 쓴다. 그때까지 이 문서는 종이로만 둔다.
설계를 미리 적어 두는 것은 공짜지만, 손대는 것은 아니다.

---

## 1. 🔴 벡터 데이터베이스는 쓰지 않는다

먼저 못 박아 둔다. **넣으면 감점이다.**

봇이 내리는 결정을 쪼개면 셋인데, **벡터가 필요한 칸이 하나도 없다.**

| 무엇 | 어떻게 | LLM 이 필요한가 |
|---|---|---|
| 내 손이 얼마나 센가 | **계산.** `shared` 의 핸드 평가가 이미 한다 | ❌ |
| 이 자리에서 몇 번째일 확률 | **계산.** 남은 덱에서 몬테카를로 | ❌ |
| 남이 3번을 집었는데 내 추정을 어떻게 고칠까 | **추론** | ✅ **여기만** |

셋째도 벡터와 무관하다. 상태가 **홀카드 2~4장 + 공용 카드 + 토큰 배치**뿐이라
**프롬프트에 통째로 들어간다.** 검색해 올 것이 없다.

벡터 데이터베이스는 **비정형 텍스트를 의미로 찾을 때** 쓰는 물건이다. 여기엔 그런 것이 없다.
「지난 판 중 비슷한 상황을 찾아 참고하자」까지 가더라도 그건 k-NN 이고, **수천 판이면
메모리에서 전부 훑는 편이 빠르다** — 벡터 저장소는 백만 건부터 값을 한다.

⛔ **진짜 위험은 면접이다.** 「왜 벡터를 쓰셨어요?」에 「요즘 그렇게들 하길래」가 나오면
**그 프로젝트 전체가 무너진다.** 안 쓴 이유를 말할 수 있는 편이 쓴 것보다 세다.

## 2. 저장소는 필요하다 — 다만 「관측」용이다

README 「무엇이 어디에 있나」가 이렇게 적어 뒀다.

> **데이터베이스를 쓰지 않는다.** 방보다 오래 사는 데이터가 하나도 없어서 뺄 수 있었다.
> 계정이나 전적처럼 서버 재시작을 넘겨야 하는 것을 넣으려면 **그때 저장소가 따라온다.**

**그 「그때」가 이때다.** 잰 것이 서버 재시작을 넘겨 살아야 하기 때문이다 — 지금은
Render 가 다시 뜨면 전부 사라지고, **사라지면 말할 것이 없다.**

### 🔴 게임 상태는 넣지 않는다

**「방은 휘발한다」는 설계 판단이지 게으름이 아니다.** 저장소를 상태의 집으로 쓰기
시작하면 방 수명 · 정합성 · 복구를 전부 새로 풀어야 하고, 지금 굴러가는 것이 깨진다.

✅ **게임은 그대로 메모리에서 돌고, 일어난 일을 옆으로 흘려 적을 뿐이다.**
쓰기가 실패해도 판은 계속된다(fire-and-forget). **적는 일이 게임을 멈추게 하면 안 된다.**

### 무엇을 적나 — 표 둘이면 된다

```
llm_call        모델 · 프롬프트버전 · 응답 · 지연(ms) · 토큰수 · 비용 · 재시도 · 실패사유
bot_decision    판ID · 라운드 · 상태스냅샷 · 고른 토큰 · 맞았나 · 판 결과 · 폴백이었나
```

`bot_decision.폴백이었나` 가 중요하다 — **LLM 이 답을 못 줘서 계산으로 때운 판**을
세지 못하면 승률이 거짓말이 된다.

### 무엇을 쓰나

**PostgreSQL 하나.** Render 에 무료 층이 있고 서버가 이미 거기 있다.

⚠️ **Contentful 은 그대로 둔다.** 계정이 이미 거기 살고 있고(`docs/context.md`),
옮기는 것은 되돌릴 수 없는 데다 얻는 것이 없다. **저장소가 둘이 되지만 성격이 갈린다** —
계정은 CMS, 관측은 시계열. 면접에서 물어볼 자리이므로 이 문단이 그 답이다.

⚠️ **README 를 고쳐야 한다.** 「데이터베이스를 쓰지 않는다」가 더는 사실이 아니게 된다.
정본은 README 이므로 **거기를 고치고 이 문서는 남긴다.**

## 3. 🔴 「정해진 것」과 부딪히는 곳 다섯

**여기가 이 문서에서 제일 값나가는 부분이다.** 기존 결정을 모르고 만들면 전부 밟는다.

### 3-1. 낙관적 UI 로 지연을 감출 수 없다

README 가 이미 정했다 — **「화면은 서버가 확정한 뒤에 움직인다. 낙관적 UI 는 뺏기가 잦은
이 게임에서 되돌리는 일이 많아 화면이 튄다.」**

그래서 **LLM 응답을 기다리는 몇 초를 낙관적 UI 로 덮는 길이 막혀 있다.** 대신 이렇게 한다.

- **봇 자리에 「생각 중」을 띄운다.** 사람이 고민하는 것과 같은 자리이고, 이 게임은 원래
  남이 언제 집을지 기다리는 게임이라 **어색하지 않다**
- **일부러 최소 지연을 둔다.** 즉답하면 봇이라는 게 드러나고 사람이 눌릴 틈이 없다
- 응답이 오면 **평소와 같은 경로로** 확정한다 — 봇이라고 다른 길을 타지 않는다

### 3-2. 라운드가 안 끝날 수 있다 — 폴백이 필수다

README — **「라운드 종료 조건이 「전원이 확정」이라 한 명이 빠지면 영원히 끝나지 않는다.」**

**봇이 LLM 응답을 못 받으면 라운드가 영원히 안 끝난다.** 그러므로

- **타임아웃(예: 8초)을 반드시 둔다.** 넘기면 **계산만으로 고른다**(확률 순위 그대로)
- 폴백은 **실패가 아니라 정상 경로**다. `bot_decision.폴백이었나` 에 적고 판은 계속된다
- **API 키가 없거나 한도가 걸려도 봇은 돌아야 한다.** LLM 은 얹는 것이지 기둥이 아니다

### 3-3. 봇이 남의 카드를 보면 안 된다

README — **「은닉 정보는 공개 상태에 담기지 않는다. `GameView` 에는 쇼다운 전까지 누구의
홀카드도 없다 — 본인 것조차 없다.」**

**봇도 플레이어다.** 서버 안에 있다고 전체 상태를 그냥 읽게 하면 **치팅이고, 그러면
승률 숫자가 아무 의미도 없어진다.** 봇에게 넘기는 것은 **사람이 보는 것과 똑같은 범위**여야
한다 — 자기 홀카드 + 공용 카드 + 토큰 배치.

✅ **`GameView` + 그 봇의 `game:hand`** 만으로 프롬프트를 만든다. 통로를 하나로 묶어 둔
덕에 이건 어렵지 않다.

### 3-4. 빌드가 없어서 `enum` 을 못 쓴다

README — 네이티브 TypeScript 실행이라 **`enum` 금지**, const 객체 + union 으로 쓴다
(`erasableSyntaxOnly` 가 잡는다). 프롬프트 버전 · 폴백 사유 · 모델 이름 전부 해당된다.

### 3-5. 한도가 있다

동시 접속 100 · 동시 방 20(`MAX_CONNECTIONS`, `MAX_ROOMS`). **봇도 자리를 차지하는가**를
정해야 한다. 그리고 **방마다 봇이 여럿이면 LLM 호출이 라운드당 여러 건**이 되므로,
비용과 속도 둘 다 여기서 터진다. **방당 봇 수에 상한**을 둔다.

## 4. 재려는 숫자

**이것이 이 일의 산출물이다.** 포트폴리오 카드의 `metrics` 칸에 그대로 들어간다.

| 숫자 | 왜 |
|---|---|
| **판정 정확도** — 프롬프트 판별로 | 「v1 42% → v2 61%」가 팔리는 문장이다 |
| **p95 응답 지연** | 백엔드가 쓰는 말이다 |
| **판당 비용** | 재시도를 포함해서 센다 |
| **폴백 비율** | 이걸 안 세면 정확도가 거짓말이 된다 |
| 사람 대비 승률 | 있으면 좋지만 표본이 모자랄 것이다 |

⚠️ **숫자는 지어내지 않는다.** 못 잰 것은 「못 쟀다」로 둔다.

## 5. 안 할 것

- **벡터 저장소 · RAG** — §1
- **모델 파인튜닝** — 크기가 안 맞고, 백엔드 지원자가 할 이야기가 아니다
- **게임 상태를 DB 로 옮기기** — §2
- **봇을 세게 만들기** — 자리를 메우는 것이지 상대가 아니다
- **Contentful 을 걷어내기** — 굴러가는 것을 옮길 이유가 없다
- **봇에게 전체 상태 주기** — §3-3. 편하지만 숫자가 죽는다

## 6. 정해야 하는 것

만들기 시작할 때 첫 판단들이다. **지금 정하지 않는다.**

| | |
|---|---|
| 어느 모델 | 비용·지연이 갈린다. 값싼 것부터 재 보고 고른다 |
| 봇도 자리를 차지하나 | 인원 수·정원 계산이 갈린다 |
| 봇이 뺏기도 하나 | 뺏기는 이 게임의 핵심인데 **봇이 뺏으면 사람이 스트레스를 받는다** |
| 프롬프트를 어디에 두나 | 파일인가 상수인가. 버전을 매겨야 하니 파일이 유력하다 |
| 혼자 해보기에도 넣나 | `dev:web` 만으로 도는데 LLM 은 서버가 필요하다 — **여기서 구조가 갈린다** |
